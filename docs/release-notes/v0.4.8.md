# OneCode 0.4.8

Windows x64 application hotfix using the complete 0.4.5 native base.

- Fix an explicit Continue or steering message waiting until the user manually clicks native Stop. The activity display could expire while the native turn was still open, dropping the steering target. The composer now retains the exact durable unfinished turn separately from Working presentation. Stop still validates the current conversation, turn and native question; only a native end releases the message.
- Stream long tool responses with ten-second keepalive comments, including modern protocol clients whose default JSON mode otherwise sent no bytes before the final result. Discovery responses keep their existing format. Authentication and tool permissions remain enforced before dispatch.
- Close interrupted MCP proxy streams as failures instead of ending truncated responses as successful. Add bounded premature-closure diagnostics without request bodies, credentials or connector URLs. No tool, Send or route mutation is automatically replayed.
- Show these repairs in What's new and retain all earlier hotfix changes.

Use **Settings → General → Check for updates → Install when done**. Compatible installations receive the smaller capsule. Fresh installations use the complete [0.4.5 base](https://github.com/hassanradwannn/OneCode/releases/tag/v0.4.5), then check for updates. Profiles and saved chats are preserved.

The transport repair covers silent long responses and interrupted upstream streams. It does not establish that every reported public TLS or provider-side disconnect has the same cause. See the [acceptance record](../release-acceptance/v0.4.8.md) for evidence and limits.
