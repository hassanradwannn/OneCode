# OneCode 0.6.1

Stable application hotfix for terminal-storage diagnostics. It does not change the immutable Windows or Linux runtime and is intended to ship only as verified application capsules.

- **Terminal storage failures now report a safe cause.** `TERMINAL_STORAGE_UNAVAILABLE` still fails closed and still guarantees that no command starts when durable terminal custody is unavailable, but it now includes a bounded diagnostic such as operating-system access denied, storage full, busy/locked, read-only, I/O error, or one of the existing path-free terminal custody validation messages.
- **Private paths and retained terminal data stay private.** Raw filesystem error strings are not forwarded to the model. Only known errno categories or explicitly whitelisted path-free storage messages are projected.
- **No replay or custody semantics changed.** Process-id allocation, incarnation history, retained output, cursor normalization, live pre-spawn custody, Stop behavior and lazy spool recovery keep their existing owners and fail-closed rules.
- **Hotfix-only delivery on both platforms.** GitHub builds Windows x64 and Linux x64 application capsules from the same frozen source. No Windows installer, AppImage or DEB is part of this release.

The minimum compatible complete base remains **0.5.9** on both Windows and Linux. The 0.6.1 capsule jobs must reproduce the published 0.5.9 runtime fingerprints; a mismatch fails packaging instead of relaxing compatibility. Current compatible 0.6.0 installations therefore update internally without downloading another complete base.

The release is publishable only after both platform capsule manifests, archives and checksum sidecars are verified and their exact entries are combined into the release `SHA256SUMS.txt` used by OneCode's internal updater.
