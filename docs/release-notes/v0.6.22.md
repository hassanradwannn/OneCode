# OneCode 0.6.22 Beta

Gemini can replace its model-picker header when the adapter closes the native menu, even when the requested model was already selected. Preparation previously treated that replacement as a failure. It now follows one successor header after its own confirmed menu action, reopens the native menu to prove the exact selected mode, and closes it within the original three-second deadline.

The original editor, draft, route, attachments and command claim remain required. A changed mode, human edit, attachment, ambiguous control, second replacement or late successor still refuses preparation. There is no model fallback, longer timeout or task Send replay. Recorder revision 83 replaces the adapter and observer together; bridge protocol 19 is unchanged.

Thirteen focused regressions cover immediate and delayed replacements, the original deadline and changed ownership. The full Gemini adapter suite passes 335 tests. This proves the repaired transition; it does not establish the cause of every native preparation failure.

Native acceptance remains in progress. Windows 0.6.21 passed ordinary queues for both providers, live ChatGPT Steer and a live page reload, and cleared the original stale failure badge while retaining its saved handoff history. Exact Resume transfer also completed, but the first resumed tool was refused and its admission path is being investigated. The first-tool, live-process and interrupted-connection gates must pass before Stable publication.
