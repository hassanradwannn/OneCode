# OneCode 0.9.8 Beta

Claude attachment questions retain their exact native text for delivery checks, including a text item beside media. A collapsed skill label or damaged instruction frame is not recorded as another authored user message. Historical structured skill chips can recover presentation without granting task authority. Upload confirmation retains one exact editor replacement and retries delayed read-only observations under the original deadline; it never repeats the upload or an uncertain Send. If an upload refusal leaves its chip in the native draft, a later human Send still reads the actual framed question without reviving the retired skill-selection proof.

API chats receive a topic title after their first validated model response, while long tasks continue. Naming asks for readable subject words and rejects folder/path labels. Older folder-style generated titles get one metadata upgrade; manual names and ordinary provider topics are preserved.

The built-in Workbench browser is discoverable before any manual tab is opened. Agents can list browsers, select OneCode Workbench and open the actual running website with `browser_tabs action=new`. That requests the sidebar only in the selected calling chat. Browser navigation remains separate from offline artifacts, which cannot connect to a local server. Starting a server by itself does not fabricate a browser-open request.

This is a prerelease for user testing. Stable 0.8.9 stays unchanged and unfrozen. Installed/native Claude, updater and unattended real-provider acceptance remain pending; automatic API compaction, API attachments and Goal stages remain unavailable.
