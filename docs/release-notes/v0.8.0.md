# OneCode 0.8.0

Add a third browser provider while keeping the workspace, tools and shared interface provider-generic.

- The provider picker now includes ChatGPT, Gemini and Claude in Setup, new chats and Remote. Existing chats, queued messages, workers and resumed tasks retain their original provider.
- Read the native account's current and legacy models, available efforts, descriptions and usage-cost hints. Upgrade, locked and disabled rows do not become available choices. Exact model and effort selections are confirmed before Send.
- Keep the native current model and effort without inventing an Automatic mode where the provider has none. Discovering its catalog does not silently select the first available model or increase thinking effort. A positively lost discovery page retires its inspection so explicit Refresh can start a fresh, nonce-scoped attempt.
- Ordinary model refresh reads current and legacy choices without cycling through models. Reasoning controls are read for the current native model; choosing another can inspect just that model in an owned empty helper. Only positively observed controls appear: native labelled levels or a binary Extended switch. Unknown or absent controls show no effort panel or loading placeholder. A switch's observed position does not silently turn current-setting intent into an explicit Off choice. Controls are never copied between models, and an older lookup cannot overwrite a newer choice.
- With the added provider selected, Setup illustrates its custom connector flow and exports an optional tailored native skill. The default stays off until the user installs and enables it. The Core connector and public HTTPS/MCP checks remain independently required.
- Account-enabled connectors are enabled once during setup. Ordinary messages, workers, Goal and Resume do not reopen or retoggle that connector or require a per-message @ mention. Local tool calls still require their exact task capability, receipt, permissions and family ownership.
- With the optional native skill enabled, a confirmed `/onecode` selection can use the task's compact guidance. Its native name and ZIP root are generic (`onecode/SKILL.md`), avoiding the provider's reserved-name rejection. An unavailable lookup uses only its prepared full-guidance fallback under the same task capability; a checkbox or literal name cannot claim that a skill loaded. With the option off, ordinary Core instructions and live context remain in use.
- Report native account limits with the displayed reset text or deadline, including a background notification for a new blocked episode. Unknown reset times remain unknown; no task is automatically replayed after a quota resets.
- Extend the existing exclusive input/Send/receipt lifecycle, local task capability admission, worker family, terminal result, scheduled check and continuation owners to the added adapter. Provider endpoints and hash-only capability ledgers stay separate.
- Preserve namespaced conversation identities when opening stored chats, preparing their browser tabs and restoring Goal/Loop objectives, switches and pending replies after restart.
- Fresh openings for the added provider use independently marked native new-chat pages. Only the same input can recover its already elected opening; a different idle home, existing chat or discovery helper cannot supply its conversation UUID. See [browser conversations and local sessions](../PROVIDER-SESSIONS.md) for parallel work and Compact & Resume ownership.
- Prepare the authored task and send it once directly, without an extra readiness greeting or preflight conversation. An uncertain dispatch retains its original receipt owner and is not replayed.
- Offer the same provider choices in the experimental local API. `/v1/models` adds `onecode-claude`; `claude` is also a routing alias. `/new`, `/provider`, Chat Completions, Responses and IDE thread mappings keep the normal outbox, permissions and canonical final-response owners.
- Compile interactive JSX/TSX components with bundled React, Tailwind, Lucide and Recharts in the existing isolated preview. Desktop and Remote retain editable source, offline Mermaid/Markdown/SVG/HTML paths and closed network access. Unknown packages and provider-only services fail visibly rather than acquiring host privileges.
- Route the optional embedded browser's Show/Sign-in through the selected provider, retain auth popups with their actual opener and prevent sign-in proof from crossing providers. The existing external browser choices use the same Companion.

Includes Stable 0.7.4's native ChatGPT picker compatibility, default Chat opening with explicit Work affinity, Gemini Thinking levels, post-warm-up model confirmation, bounded optional skill lookup and delivery preparation improvements.

The account's native UI remains the authority for models, limits and connector availability. Free and paid accounts use observed choices rather than a hard-coded plan catalog. Workspace policy and provider rollouts can make native features unavailable.

See [verification scope](../release-acceptance/v0.8.0.md) for automated checks, native evidence and unexercised lanes. Cloud build, package compatibility, publication and installed/native acceptance are separate facts; release receipts are recorded after their checks finish. Application tags remain pinned to the frozen source when later documentation advances the branch.
