# OneCode 0.3.7.1

Windows desktop update with remote connection repairs and interactive browser previews. This repair is newer than the 0.3.7 test installer and is delivered through OneCode’s built-in updater.

- **Remote mode:** Settings → Remote → turn on → Copy link. Open the link in a browser on a device connected to your Tailscale. OneCode configures private Serve itself and selects a free port without changing existing routes. The React browser interface talks directly to host OneCode for chats, history, task titles, messages, Stop and safe preferences.
- **Remote reliability:** history uses the server's shared page limit and a live revision cursor. Successful sends no longer become a false reconnect caused by an invalid history query. Long task titles stay in their rows; settings and phone controls remain accessible.
- **Tailscale recovery:** broader executable discovery, automatic resumption after prerequisite approval, direct setup actions and numbered recovery steps with copyable PowerShell service/firewall commands. Public connector readiness now includes MCP initialization after public DNS, TLS and metadata checks. Private Remote never requires public Funnel permission.
- **Interactive previews:** choose a 16:9 desktop browser viewport (1600×900) or a 9:16 phone viewport (450×800). The same live page scales to fit the chat card, workbench or fullscreen area without changing its layout or losing state. Sidebar previews receive the available panel height, and fullscreen controls clear the Windows title bar. Preview no longer forces extra document scrollbars; the page retains its authored scrolling. Core plugin discovery includes the built-in canvas; cached skills using kind="html" use the same guarded artifact owner.
- **Windows release:** explicit OneCode window branding and a dedicated taskbar ICO, packaged updater configuration and helpers, architecture-specific feed and blockmap, and verified release checksums for internal updates.
- **Immediate direction changes:** Send during an active response stops that exact native turn, waits for its confirmed end, then delivers the new message through the existing outbox. Idle Send starts an ordinary response. Explicit after-turn queuing remains available.
- **Provider choice for each new chat:** the desktop header and remote browser use the shared provider registry. Changing provider replaces the model catalog. The first submitted message hides the provider switch; the chat keeps that provider. The existing model and thinking-effort controls remain available.
- **Chat-first presentations:** both providers can begin a Core artifact or approved local image presentation, show an animated Generating square, then complete it inline in chat. Live Core instructions, plugin discovery and the bundled provider skills advertise this built-in interactive canvas, including a Core exec fallback for cached schemas. Reusable canvas guidance stays in the skills and connector rather than repeating in chat messages. Interactive previews run in an isolated document; creating an artifact does not open the workbench. The model can explicitly present it there, or the user can expand it. Background presentations cannot navigate away from the selected desktop chat.
- **Embedded workbench:** local artifact previews, revisions, comparison and export; browser and media panels. Media saves retain their witnessed source conversation across compaction and validate the destination before publication. Existing full-page Pets, Plugins and Skills navigation is preserved.
- **Gemini native output import:** generated images appear inline and can save their rendered pixels as PNG. Generated videos use the shared poster, playback and original MP4 export path. Native HTML Canvas source becomes an inline interactive presentation with local revisions and an optional workbench. Ordinary code replies remain normal chat content. These source capabilities still require acceptance in the updated desktop and companion.
- **Responsive remote composer:** one combined model/effort menu, chat mode beside the model on phones, icon navigation, circular Send/Stop and the Add photos & files / Skills menu. Remote uploads use the existing attachment owner, with a 16 MB limit per file. The app fits the viewport; long chats and settings use OneCode's scrollbar styling.

The host PC, OneCode and Tailscale must remain running. Remote mode uses its own private Serve listener and remote-only access key; it does not connect through or replace a provider's MCP connector. It preserves unrelated Serve/Funnel routes. Turning Remote off invalidates its link and browser sessions.

See [release validation](../release-acceptance/v0.3.7.md) for the scope of completed checks and remaining acceptance limits.
