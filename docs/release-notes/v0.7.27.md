# OneCode Beta 0.7.27

This Beta supersedes the unaccepted 0.7.26 candidate. The readiness repair itself is unchanged, while the release workflow now completes the canonical checksum register that installed clients require before a candidate can be accepted.

- An exact durable native Send acknowledgement promotes readiness for the same selected session, conversation and browser, even if an earlier selection probe timed out.
- ACK-derived readiness is published before the existing session-change notification, preventing the renderer from racing ahead with an older terminal refusal.
- Late reconciliation remains read-only: it does not reopen, focus, reload or resend the provider tab.
- The release workflow now waits for both platform uploads, merges their verified checksum sidecars, validates every referenced GitHub asset digest, refuses conflicting canonical content, and publishes SHA256SUMS.txt while the release is still an unpublished draft.

Beta 0.7.26 was not accepted because its published asset set omitted that canonical checksum file, causing the 0.7.25 updater to fail with HTTP 404 before any install occurred. No 0.7.26 installed-app acceptance is claimed.

Stable promotion remains blocked until 0.7.27 is installed through the native Beta updater and passes the selected-chat readiness acceptance without reselecting, reopening, focusing or resending the provider conversation.
