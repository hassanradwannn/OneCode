# OneCode 0.7.2 Beta candidate

Native acceptance located a browser maintenance stall at the rendering-policy stage. Rendering reconciliation now tracks each tab independently. A hung attachment, focus acknowledgement or release cannot hold opening and message pickup for other tabs.

Callers stop waiting within a bounded interval while the original browser operation retains its custody until its actual reply. The same tab cannot start a second attachment because that wait expired. Late replies recheck the current route, activity, permission and cancellation before declaring rendering ready, and revoked attachments retain their cleanup path. Unknown permission reads grant no rendering access. The existing debugger surface remains limited to focus emulation.

This candidate is undergoing native acceptance. Stable 0.7.0 remains unpublished until those gates pass.
