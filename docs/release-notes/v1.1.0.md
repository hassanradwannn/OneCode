# OneCode 1.1.0

- Capture ChatGPT visual styling from the mounted native response, including class-based spacing, rounded corners, typography and SVG paint.
- Preserve responsive authored dimensions in the offline snapshot. Media and portable reply controls retain their existing import owners.
- Show surrounding prose without pasting an imported visual's labels into the transcript a second time. Full canonical text remains available for copy and export.
- Refresh the display of an existing completed reply only when its canonical text is unchanged and the omitted native visuals are already retained under that exact reply.
- Retain complete code blocks from ChatGPT's current native Copy payload, including lines outside the editor viewport, indentation and language.
- Fit native visual previews to their content width and height, with bounded scrolling for tall content.
- Center provider-imported artifacts and diagrams without a title bar, border or Fit selector. Keep one fullscreen control; artifacts created through the Core tool retain their full toolbar and viewport controls.
- Apply the same native preview sizing in Remote, including restoring content fit after leaving an expanded preview.
- Keep an intentionally empty native display projection empty in Remote, so a visual-only reply does not regain its flattened labels through the plain-text fallback.
- Serve bundled Remote fonts as local assets so mathematical glyphs remain compatible with its existing content policy.
- Re-render captured native KaTeX from its public formula source, preserving superscripts and fractions on Desktop and Remote without trusting provider markup.
- Remove the generic per-reply "Open interactive content in provider" button from Desktop and Remote. Native controls no longer cause an extra fallback row.
- Ignore empty Gemini accessibility alerts instead of reporting a blocking provider failure. Empty historical notices no longer appear on Desktop or Remote; real notices and explicit limit evidence remain available.
- Render HTML artifacts that use the standard Tailwind CDN entrypoint with the bundled offline compiler, including interactive class changes, rather than dropping their layout dependency.
- Recognize Claude's published artifact cards separately from generated-file cards. Import the selected native viewer's public HTML export only after its artifact, output path, reply and conversation agree.
- Support both observed Claude published-card layouts, including button cards whose selected artifact is proved by the exact native viewer route and frame identity.
- Follow Claude's completed edits of the same published artifact UUID, retain local revisions and show the updated artifact at its owning reply. Multiple current cards for that same native frame no longer block import.
- Retain Claude's rendered Mermaid diagrams from their public shadow roots, including native SVG geometry, theme, spacing and labels, instead of losing them during Markdown capture.
- Require exact native message ownership before importing or removing a visual from its display capture. Updated Companion readers replace the prior pair together.

Complete Windows x64 installers and Linux x64 AppImage/DEB packages accompany cumulative application capsules. Windows capsules use the verified 0.5.9 complete base; Linux capsules use 1.0.7. Internal updates retain the platform's native compatibility checks and preserve the existing profile.

Offline previews retain standard HTML controls and supported bundled artifact runtimes. Provider-only event handlers and services still require the original provider chat; this release does not claim universal behavior parity for those controls.
