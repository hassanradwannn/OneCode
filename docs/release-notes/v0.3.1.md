# OneCode v0.3.1

Installed plugins and skills are easier to discover in existing ChatGPT and Gemini chats.

- Core now always exposes the local `plugins` discovery bridge, including before the first plugin is installed. Newly installed tools are discovered through the live local catalog rather than a marketplace search.
- Existing OneCode chat turns remind the provider to discover installed plugins and read relevant skills from the live `/skills/.catalog.json` catalog. No new conversation, slash command or separate Plugins mention is required for this workflow.
- Explicit skill selections, frozen automatic routing, project scope, Read-only, Block/Trust and caller identity checks retain their existing boundaries. Installation and sign-in remain separate actions.

Update through **Settings → General → Check for updates**, then choose **Install when done** when the download is ready. The Windows x64 release includes the updater metadata, blockmap, checksums and matching 0.3.1 Companion. Very old packages missing updater metadata require one manual installation. Provider-native chats outside OneCode's delivery path do not receive its per-turn reminders; provider tool caching may require a one-time Core refresh.

Validation includes cross-provider existing-chat prompt paths, live skill/plugin catalogs, later installation/removal, project isolation, permission checks, file attachments, parallel input and Windows updater/download regression tests. TypeScript, production build and packaged Windows runtime checks are required before publication. Model adherence still depends on the provider; tool results establish actual discovery and execution.
