# OneCode 0.6.5 Beta candidate

This candidate includes the 0.6.4 recovery, Stop/steering, idle browser startup, file-link and centered-preview fixes, plus a startup hang reproduced during Linux Beta acceptance.

A fresh explicit message authored after confirmed native Stop can restart the chat without waiting for the prior soft activity timer. Earlier queued work and automation remain held. Exact running tools, newer questions or work, provider identity and native Send readiness remain fences. This was reproduced in live Gemini acceptance and regression-tested for both providers.

An unanswered operating-system credential-storage call now releases its caller after 15 seconds. Startup and desktop state reads can proceed with a truthful unavailable-storage status. Protected operations remain closed until the OS call responds. Existing encrypted credentials and installation identity remain untouched; late encryption or decryption results cannot modify them. Linux's insecure hard-coded-key fallback remains refused.

The underlying native call remains tracked for bounded shutdown. Calls do not accumulate behind an unanswered prompt, and a later operation can retry after it settles. This does not reset or unlock a locked desktop keyring.

Windows and Linux, ChatGPT and Gemini, and Desktop and Remote acceptance are tracked separately. Stable promotion remains pending that acceptance. The reported overnight Windows crash is not yet attributed to a confirmed exception; the reproduced startup hangs alone do not prove its cause.

Complete Windows/Linux Beta releases and compatible application capsules are built on GitHub from the frozen candidate source. The Experimental local API remains opt-in, authenticated and loopback-only. Existing provider/session, permission, task-authority and runtime-compatibility boundaries remain in force.
