# OneCode 0.6.2 Beta

Experimental Beta release for the new local OneCode API. The API lets IDEs and other same-computer clients talk to the OneCode agent through an OpenAI-compatible HTTP surface while keeping OneCode's existing browser-provider, tool, skill, plugin, permission and durable-send owners.

- **Use OneCode as a local OpenAI-compatible endpoint.** Enable **OneCode API (Beta)** in Settings, copy the loopback base URL and the per-device API key, and configure a client with `GET /v1/models`, `POST /v1/chat/completions` or `POST /v1/responses`.
- **Control the actual OneCode app.** `/new` creates and selects a durable OneCode chat, `/provider` selects ChatGPT or Gemini for subsequent new/unbound chats, and `/session` selects an existing normal OneCode chat. Existing bound chats keep their provider.
- **The API agent retains OneCode abilities.** HTTP requests enter the ordinary durable input path; the provider turn receives OneCode's normal Core surface rather than a parallel HTTP tool implementation. Files, terminal, browser/desktop methods, workers, skills and installed plugins therefore retain their existing permission and identity checks.
- **Capabilities are live.** `/v1/onecode/capabilities` is recomputed from the Core surface, enabled desktop methods, current permissions, plugin manager and skill library. Adding/enabling a skill or plugin does not require restarting the API listener.
- **Persistent per-device authentication.** The bearer key is stored only in OS-backed encrypted secret storage, survives restarts and compatible updates, is copied directly by the trusted desktop without entering renderer state, and can be rotated explicitly.
- **Off means off.** The feature is disabled by default. With it disabled, there is no OneCode API listener or API-specific background work.
- **Local-only boundary.** The server binds to `127.0.0.1`, validates its loopback Host, rejects browser Origin requests, uses constant-time bearer comparison, bounds JSON request bodies and never exposes the key through API status/capability responses.
- **Ambiguous delivery is never replayed.** If an API client disconnects after OneCode admits an input, the HTTP wait ends but OneCode retains that input's ordinary custody. The API does not infer cancellation or resend the request.

The supported HTTP compatibility in this Beta is intentionally text-in/text-out. Files/images and other provider-native OpenAI request fields are not claimed as HTTP compatibility yet. One API completion is serialized at a time while the device-level current-chat model is experimental. See [OneCode API (Beta)](../ONECODE-API.md) for configuration and endpoint details.

## Beta update path

0.6.2 publishes complete Beta install artifacts for Windows and Linux alongside the already-accepted application capsules. New Beta users can install the current Windows installer or Linux AppImage/DEB directly. Existing 0.5.7 Beta installations can receive the smaller 0.6.2 capsule through the internal Beta updater because both platform capsule builds reproduced the published 0.5.7 immutable runtime fingerprint. Any runtime or channel mismatch fails capsule packaging closed.

The published stable channel remains unchanged. This release uses the separate `beta-v0.6.2` channel/tag and does not move or replace stable release artifacts. The Beta tag remains pinned to its original frozen 0.6.2 source while release tooling on the `release` branch can backfill missing full artifacts without rewriting that tag.
