# OneCode 0.5.1 — reliability repair candidate

This is an unreleased candidate. Source checks, packaged builds, installed Beta acceptance and publication are separate gates; the acceptance record tracks their actual status.

- Preserve exact chat authorization and Remote device access across ordinary reconnects, sleep and restart without clock-based expiry.
- Separate completed terminal output from live process capacity. Retain output across crashes, expose background work per process, and stop commands owned by an explicitly stopped chat. Track inherited WSL descendants by an exact run token and process start identity.
- Offer **Update now** alongside **Install when done**. Shutdown verifies termination and saves output before handing off installation; unconfirmed termination keeps the update from proceeding.
- Distinguish installed AppImages, verified DEB packages and unpacked QA builds. QA profiles and single-instance locks are isolated from normal installations.
- Support verified Linux application hotfixes on AppImage and DEB installations. AppImage full upgrades can stage a required base and its cumulative hotfix together and launch the final version once. Full DEB/native upgrades remain package-manager-owned.
- Preserve durable Stop, Continue and Compact & Resume intent while the exact provider page becomes ready. Never automatically replay an uncertain Send or tool operation.
- Use the exact connector name configured in Setup for selection and automatic approval. A card naming another connector shows the mismatch and remains untouched.
- Label packaged Betas as **0.5.1 Beta**, with separate installation identity, user data, browser bridge ports and update feed. Beta full updates and hotfixes remain in the Beta channel.
- Center the background-work dialog and retain late commentary revisions in desktop and Remote history.

## Updating

The Linux bootstrap and profile-isolation changes require a complete new AppImage or DEB base. Once installed, later compatible application capsules can update internally. Windows and Linux AppImage composite updates verify both the required full base and hotfix before one install action and one successor launch.

Profiles, projects, chosen browser, connector settings and saved chats must survive the update. Beta acceptance uses isolated profiles and does not replace production sessions.
