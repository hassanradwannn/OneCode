# OneCode 0.6.0

Stable application hotfix focused on recoverable history access, Windows installation data, Remote responsiveness and Linux updating without changing the immutable Windows or Linux runtime.

- **History access failures retain their real meaning.** An OS-denied journal is preserved and cannot be mistaken for empty history or an absent tail. Task admission reports storage unavailability separately from revoked authorization for both providers, retains the existing exact grant, and starts no tool while its proof cannot be read. No uncertain message, tool or append is replayed automatically. Removal of an external access block permits the same exact grant to be checked again.
- **Windows data lives beside the installation.** On a normal launch, the default Roaming profile is copied into a private per-user folder named `OneCode Data` beside the install directory, verified file by file, and published atomically. The original remains a backup; cached installers and Chromium process locks are excluded. App-owned plugin launch paths follow the new location. Explicit isolated profiles stay isolated. A protected installation parent uses per-user Local data instead. The updater's first successor retains its exact original profile to finish its receipt; migration occurs on the next normal launch. Linux retains its existing verified bootstrap/profile contract in this hotfix.
- **Interrupted downloads can resume.** The updater retains partial artifact bytes after a network interruption, rehashes the saved prefix, validates the server's returned byte range, and verifies the completed published SHA-256 before staging. A server that ignores Range starts a clean transfer rather than appending a second full file.

- **Remote reaches useful content sooner.** Authenticated Remote reads no longer launch two Tailscale CLI status commands on every API request. A recent successful private-route proof is reused for foreground reads while the existing five-second watcher still performs forced route verification and immediately suspends admission if route custody, node identity, or private Serve state changes. The token-validation bootstrap is also handed directly into the workspace instead of being discarded and fetched again.
- **Linux text uses the native UI fallback first.** The renderer now prefers `system-ui` before platform-specific and CJK fallbacks. This avoids the oversized spacing seen around apostrophes and other Latin punctuation on Linux without modifying saved or displayed message text.
- **Linux full-update downloads visibly move.** AppImage downloads now report received bytes and, when the transport supplies a usable Content-Length, a live percentage. The transport length is presentation-only: the completed artifact still has to match the release SHA-256 before it can become installable. Hotfix and combined-base downloads retain their published-size progress path.
- **Stable capsules are built in GitHub.** The draft release workflow now has a real `stable-capsule` operation for Windows x64 and Linux x64. It requires an already-published compatible base, packages only the mutable application layer, runs packaged-runtime smoke on the stable channel, validates the runtime/base binding, and uploads only curated checksum-listed capsule assets.

The intended minimum complete base is 0.5.9 because published 0.5.9 and 0.5.10 base descriptors carry the same immutable runtime fingerprints on both Windows and Linux. The 0.6.0 GitHub package jobs must reproduce those fingerprints; otherwise capsule packaging fails closed and a full release is required instead.

The GitHub jobs run public verification (privacy, notices, types and production bundles) and packaged-runtime smoke before uploading capsule assets. Private local regression suites remain outside public Git. Validation and installed hotfix acceptance are recorded from the frozen release source before publication. A GitHub draft, downloaded capsule, or staged update is not by itself an installed acceptance result.
