# OneCode 0.6.20 Beta

ChatGPT model preparation could repeatedly read its own native metadata changes while opening a Compact & Resume destination. Those reads could starve rendering, route cancellation and timeout tasks, leaving a saved handoff waiting in a blank destination chat. Mutation-triggered readback is now coalesced onto the next event-loop task. Exact account availability, model, effort, route and Send guards remain required.

Gemini can replace its model header after an authorized selection click. The adapter now permits one such replacement within the original selection budget while retaining the original editor, draft, route, attachments and command. It still reopens the native menu and proves the exact requested selected model ID; earlier or repeated replacements, a different selection or changed ownership refuse the operation.

A failed handoff's old composer badge now clears after a different native user question is confirmed in the same chat. The durable failed handoff and its saved summary remain in history; typing an unsent draft or losing question identity cannot clear the active badge. The English generic wait caption now identifies OneCode as the observer rather than implying that the provider reported a pending operation.

Bootstrap model failures retain their bounded adapter checkpoint in diagnostics without task text, tokens or private URLs. This candidate retains the 0.6.19 exact native approval-name, guarded Steer refresh and resumed-command restoration fixes, together with the 0.6.18 transport lifetime, progress, delivery, failed-notice cleanup and updater repairs. Bridge protocol 19 is unchanged; recorder revision 81 replaces the adapter and observer together.

Windows and native Ubuntu acceptance is still in progress. Stable publication remains blocked until destination preparation, the exact first resumed tool, interruption recovery, queue and Steer pass their required native checks.
