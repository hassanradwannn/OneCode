# OneCode 0.6.18 Beta

The Companion could treat a recoverable transport notice as a failed turn, ending the task proof while local work continued. Connection notices and the silence watchdog now remain observations until a native completion, true failure, explicit Stop or superseding question supplies the actual boundary. Fresh running-tool activity for the exact recorded turn advances the progress clock. Stop, revocation, attachment and exact Send receipt checks remain in place.

An already open provider tab could have lost its content observer after an extension reload. Input delivery now immediately invokes the existing observer-restoration owner in the elected tab instead of waiting for the one-minute sweep. Restoration does not open another tab, authorize a Send or replay an uncertain delivery.

Native connector chips could be mistaken for an unsent text draft, and the Send reader could include them in the expected question even though native message readback excluded them. Draft checks, insertion and Send readback now agree on authored text. Genuine drafts, attachments, trusted edits and changed documents remain protected.

A new explicit follow-up after a recorded failure can use the ready native composer while an old local request finishes. Earlier queued automation cannot use that exception. Reopening a selected chat no longer mistakes clearance of its old closed-tab marker for another closure. Fresh work also interrupts serial idle-tab cleanup before another page probe or closure, allowing the maintenance owner to collect current input promptly.

When Node's public update request cannot connect, the updater can try Chromium's normal network transport within the same deadline. It sends no credentials and retains normal TLS, channel, release, checksum and installation validation. This fallback does not retry Send, Stop, installation or any other mutation.

Failed automatic messages disappear from chat after thirty minutes and can be dismissed earlier with ×. Their durable delivery receipts remain retained for late acknowledgement and task-proof checks. A completed-response notice now states what OneCode actually observed rather than claiming that recovery completed every task step.

Bridge protocol 19 is unchanged. Recorder revision 79 replaces the adapter and observer together. This is a Beta acceptance candidate; Stable remains on 0.6.17 pending the native Windows and Ubuntu acceptance results.
