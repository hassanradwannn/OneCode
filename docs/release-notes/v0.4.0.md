# OneCode 0.4.0

Windows x64 release for ChatGPT web and Gemini web. See the [release acceptance record](../release-acceptance/v0.4.0.md) for validation scope and limits.

- OneCode Core brings permitted files, terminal, browser/window tools, installed integrations and managed skills together. Existing chats discover current tools through the live `plugins` gateway. The older Desktop and Plugins endpoints retain compatibility.
- Remote groups chats by their OneCode project and preserves each project's new-chat draft, attachments, plan and delivery receipt. Existing chats retain their provider and workspace.
- Native steering stops the selected response and waits for its exact turn-end receipt before sending the original correction as a new message. Corrections are not substituted into MCP responses. Block still prevents admission.
- Core `automations` saves a requested interval and check message in the exact chat. OneCode repeats the message until cancelled, using the same durable outbox and native Send acknowledgement. Desktop and Remote expose the saved schedules and cancellation. The PC must stay awake, OneCode running and the provider signed in. A sent message is not evidence that a check succeeded; the agent must inspect real process errors and outputs.
- Windows setup can start the exact Tailscale package through Windows Package Manager, retains installer and OS consent, and opens the installed Tailscale account UI. Unsupported or failed native setup has a first-party manual fallback. MCP and Remote share setup launch custody and resume only after real prerequisite verification.
- Browser detection, Gemini cold model refresh, recorder recovery and restored opening custody retain the original provider, account, document and input. An uncertain Send is never replayed automatically.
- Image cards and recovered previews retain their exact response/file identity. ChatGPT and Gemini use separate native output adapters; Gemini's rendered image export is identified separately from an original file download. Tool-backed artifact and local file presentation uses the same Core owner on both providers.
- Both models receive instructions for presenting approved local photos and MP4/WebM video files. Videos up to 128 MiB are retained in chat history and played through bounded authenticated transfers on desktop and Remote.
- Cold-boot daemon read failures retry automatically before route publication. Remote temporarily refuses admission during a network/daemon interruption, then verifies the same retained route before recovering. Changed routes and identities fail closed. Loaded Remote pages time out stalled connections and offer Reconnect; ambiguous actions are not automatically resent.
- Shared controls and optional native skills use OneCode branding. Required legal and upstream attribution remain intact.

## Updating

Use Settings → General → Check for updates, then Install when done. The normal profile, chats, projects, permissions and connector paths are preserved. Each installation keeps its own URLs and credentials.

Keep the host awake, OneCode running, Remote enabled when needed, and Tailscale signed in on the relevant devices. OneCode cannot bypass carrier/firewall restrictions or a captive portal. Native account approval and OS installation consent still belong to the user. Browser-level failures before the Remote page loads require restored reachability and a reload of the saved bookmark.
