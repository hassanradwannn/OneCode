# OneCode 0.4.5

Hotfix downloads now show progress as data arrives instead of staying at 0%. A download reaches 100% only after checksum verification and staging. Full-installer downloads are pinned to their selected release tag, fixing a race where publishing a newer hotfix made the downloader look for the selected installer on the wrong release.

If a future hotfix requires a complete release an installation missed, OneCode verifies both releases' checksums and the exact base descriptor, downloads the base installer and hotfix, then offers one **Install when done** action. After active work finishes, the detached updater installs the base without opening it, applies the verified hotfix and opens only the final version. Compatible installations retain the smaller hotfix-only path. Invalid or altered plans fail before base installation; an unexpected running successor is left alone.

**0.4.5 is a complete Windows x64 release**, containing the 0.4.4 What's new pane, Settings reopening, modal deferral, and all earlier connection recovery and timeout fixes. Full releases remain cumulative: they include the hotfixes already merged into main. This release publishes an installer and verified base descriptor so older clients can get the repaired updater through their existing update action.

Use **Settings → General → Check for updates → Install when done**, or run the installer from this release. Profiles, chats, permissions and saved connector URLs are retained. After restart, What's new summarizes the installed version; reopen it in **Settings → General → What's new → View changes**.

The base installer is not automatically replayed after an uncertain failure. If the later application patch fails with no successor running, its backup can restore the newly installed base; this does not roll the native installer back to the previous runtime. A running unconfirmed successor is not terminated or overwritten. See [validation](../release-acceptance/v0.4.5.md) and [hotfix publishing](../HOTFIX-UPDATES.md).
