# OneCode Beta 0.5.7

Windows and Linux Beta validation release for the reliability update planned for stable 0.5.9.

- Repairs completed-terminal delivery receipts and safely recovers legacy terminal cursors while retaining unread output. Restored completions do not consume live process slots.
- Recovers reusable worker families across chat transitions and improves Stop handling for durable turns, waking workers and exact owned processes.
- Applies explicit standalone written folder grants immediately. Share a folder now opens folder approval directly, preserving the current chat and draft.
- Preserves session history when journal access is denied, retries transient open failures and provides Reload chat after access is restored.
- Improves Remote history loading, attachment previews/removal and worker grouping, and keeps control API history cursors consistent.
- Keeps native skill openings compact and translates Companion connector-mismatch guidance.

Validation completed: public verification/build, Windows packaged runtime smoke, focused owner regressions, native Windows message delivery and desktop adoption, current-chat folder grants, Stop followed by another command, controlled journal lock/reload, and native Linux recovery of retained terminal results on an isolated profile copy.

Known limits: the inherited broad test suite is not fully green. A persistent operating-system denial on an existing journal is separate from transient lock recovery and is not claimed resolved by this release. Installed Windows 0.5.5 and Linux AppImage 0.5.3 both completed native internal updates to 0.5.7, preserved their acceptance profiles and relaunched visible windows. Stable 0.5.9 has not been published.
