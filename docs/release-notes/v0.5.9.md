# OneCode 0.5.9

Reliability repairs for existing chats, local terminals and Windows/Linux updates.

- Completed terminal results retain their exact delivery receipts, release live process capacity and recover legacy display cursors without rerunning commands or discarding unread output.
- Sleeping workers remain reusable across chat handoffs. Stop follows the durable unfinished turn, waits for the provider boundary and cancels exact owned terminal work, including pending launches.
- Standalone explicit written folder approvals and the composer folder picker grant access immediately in the current chat. The picker preserves the selected chat and draft.
- Journal open failures receive bounded retries. An inaccessible journal remains preserved, and Reload chat restores the conversation after file access returns. Persistent operating-system access denial still requires file access to be restored; the updater does not reset or replace that history.
- Remote loads earlier history while scrolling upward, previews image attachments, separates removal from preview and groups workers beneath their parent. Local control API pages use consistent immutable history positions.

Validation includes focused owner regressions, packaged runtime checks and native Beta acceptance for message delivery, current-chat folder grants, Stop followed by another command, controlled journal lock/reload and Linux retained-terminal recovery. Installed Beta Windows 0.5.5 and Linux AppImage 0.5.3 both updated internally to 0.5.7, preserved their acceptance profiles and relaunched visible windows. The inherited broad test suite is not claimed fully green.
