# OneCode 0.7.4

Updates native model discovery and selection, and reduces avoidable browser preparation delays.

- Reads both ChatGPT native picker layouts, including Work's merged model picker, its Default recommended group, account-visible model families and reasoning lanes. Discovery preserves a readable native surface, restores the original selection and refuses ambiguous menus.
- New ChatGPT chats default to Chat. An explicitly selected Work model carries its observed surface through saved defaults, queued messages, workers and Compact & Resume, and verifies the exact model after the native transition.
- Supports Gemini's native Thinking level submenu, observing available levels under the selected model and confirming the actual selection before Send.
- Verifies Gemini's requested model again after fresh-chat warm-up changes the conversation. A changed model or stale document stops preparation before the task is authorized or sent.
- Bounds optional native skill lookup and preserves the original draft when that skill is unavailable. Core connector preparation and exact task authorization remain required.
- Moves unrelated keep-awake bookkeeping behind owed input delivery and checks reusable idle documents concurrently before selecting one exact preparation owner.
- Fixes a Steer race when the provider temporarily exposes no DOM user row: existing exact native-source proof is retained and the pending frame commit is joined before the sole Send. Missing or changed ownership still refuses delivery.

This release retains the existing Windows and Linux internal-update compatibility contract. Native menu inspection, automated regression checks and packaged verification are recorded separately; no task Send is inferred from inserting text or selecting a model.

See [verification scope](../release-acceptance/v0.7.4.md) for the native observations and unexercised acceptance lanes.
