# OneCode 0.6.17 candidate

This candidate repairs an acceptance blocker found in an existing Gemini chat. During a native refresh, a previously proved approval reply could appear before its historical source node. The recorder then treated that old reply as a new user question, changing the current task and preventing a queued Steer from completing its refresh handshake.

The Gemini adapter now withholds only an exact previously proved reply whose decision text is unchanged until its source is available. Genuine unreceipted instructions and edited replies remain ordinary user messages. Refresh readiness also waits for approval receipt restoration. This adds no automatic approval, task authorization or historical-message rewriting.

The release includes the earlier fixes for Steer and queued follow-ups alongside local processes, long Compact & Resume task authorization, independent chat pickup, native host pairing and updater shutdown cleanup. Compatible application capsules remain available for Windows and Linux; matching complete bases and native runtime fingerprints are still required.

Protocol 19 is unchanged. Recorder revision 78 loads the repaired adapter and observer together. Focused Gemini and full content regression batches passed before version alignment; native capsule acceptance and final release checks are in progress. Automatic approval work remains deferred.
