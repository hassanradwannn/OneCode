# OneCode 0.6.17

Gemini could restore an old approval reply before the historical question that gave it meaning. The recorder then treated that reply as a new user question, leaving a queued Steer unable to finish its refresh even after the local poll ended. Recovery now preserves the classification of an exact previously proved reply while its source history loads. Genuine unreceipted instructions and edited reply text remain ordinary messages. Readiness also waits for approval receipt restoration.

The release includes the earlier fixes for Steer and queued follow-ups alongside local processes and in-flight polls, long Compact & Resume task authorization, independent chat pickup, native host pairing, Companion coexistence and updater shutdown cleanup. Steer preserves the original local task and its output. Automatic continuation retains its separate source and completion checks.

Complete Windows x64 and Linux x64 downloads are included for fresh installations. Compatible existing Stable installations use the smaller verified application capsules, approximately 23.5 MB each, through Settings → General → Check for updates. Both capsules retain the published 0.5.9 minimum complete base and require a matching native runtime. Install when done lets active work finish before the update restarts the app. Full DEB/native changes remain package-manager-owned.

Protocol 19 is unchanged; recorder revision 78 loads the repaired adapter and observer together. Both platform release builds passed public verification and packaged runtime smoke checks. The [acceptance record](../release-acceptance/v0.6.17.md) distinguishes the earlier repair matrix, focused 0.6.17 retests and installed updater evidence.

Provider approval cards may still need manual Allow or Allow once. Automatic approval changes are deferred. Existing historical messages are retained; this repair does not rewrite old task history or resurrect retired credentials. Production workloads remained running during acceptance; the authorization repair becomes active in an older installation only after its 0.6.17 update completes.
