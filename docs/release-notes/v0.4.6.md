# OneCode 0.4.6

Windows x64 application hotfix for the complete 0.4.5 base.

- Fix a missed turn registration when an acknowledged browser message is mounted but its source is temporarily unreadable. This could leave a long handoff waiting two minutes before local session authorization was rejected, while a fresh retry worked.
- Recover from the existing exact accepted Send receipt, retaining the chat, native message, document lifetime and generation checks. Do not resend the message, extend credentials or accept an older task's authorization.
- Update the Companion recorder so existing managed pages receive the repair, and show this fix in What's new after activation.

Use **Settings → General → Check for updates → Install when done**. Compatible 0.4.5 installations download the application capsule. The updater verifies and stages the declared complete base first when required, then applies the hotfix before one final launch. New users install the [0.4.5 Windows base](https://github.com/hassanradwannn/OneCode/releases/download/v0.4.5/OneCode-Setup-x64.exe), then check for updates. Chats, settings, permissions and connector URLs are retained. If an older updater cannot offer this hotfix, install the complete 0.4.5 base first, then check again.

This fixes a reproduced recorder gap consistent with the reported failure. The historical browser state was not retained, so it is not a claim that every authorization error has the same cause. See the [acceptance record](../release-acceptance/v0.4.6.md).
