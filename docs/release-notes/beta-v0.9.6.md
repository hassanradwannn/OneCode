# OneCode 0.9.6 Beta — output and terminal recovery

- Replace the fixed 16,384-token response ceiling with model/context-aware output budgets. Start with up to 65,536 tokens, or the selected model/context ceiling if lower. Unknown model ceilings use a 32,768 fallback. A length boundary raises the budget up to the advertised model/context ceiling and automatically continues the same task. Nemotron 3.5 Super VL free currently advertises 131,072 completion tokens.
- Preserve safe partial public text and completed tool results. Never execute length-truncated function proposals or forward incomplete reasoning signatures as complete items. Permit three consecutive automatic output continuations before a specific no-progress error; the task checkpoint and processes remain retained. Empty completions enter bounded inference recovery, while content-policy stops require attention.
- Repair API terminal result publication and acknowledgement. Results are acknowledged through the existing exact session/turn owner after their model-facing delivery is confirmed. A failed request or clipped result cannot acknowledge unseen output. Native terminal renderings and bounded background pages fit the API's new 64,000-character result allowance.
- Re-offer restored terminal prefixes from their durable acknowledged cursor. An initial offer offset is not evidence that the output reached the model. Old unread results can be collected without clearing the spool or rerunning their commands; another chat's results stay isolated.
- Detect identical EXEC_RESULTS_UNREAD decisions, guide the agent away from PING loops and report genuinely stalled recovery after eight unchanged model decisions. Parallel calls in one response do not count as repeated decisions; advancing output pages do not count as a stall.
- Clarify that unread output is separate from command permission. Existing write_stdin Ctrl-C interrupts an exact owned hung pipe test without launching a fresh exec; a port number or guessed OS PID never proves ownership.

Model output ceilings and reasoning sharing that budget are described in [OpenRouter's model catalog](https://openrouter.ai/nvidia/nemotron-3.5-super-vl:free) and [reasoning guidance](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens). Automatic continuation can use additional provider tokens. This does not make API context unlimited: automatic compaction, attachments and Goal stages remain unavailable.

Stable remains 0.8.9. Its next release stays unfrozen and unpublished pending user acceptance. Native/installed/live-provider and physical Remote testing remain separate from local fixtures and GitHub package checks.
