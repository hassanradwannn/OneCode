# OneCode 0.9.0

Stable 0.9.0 includes the complete repair series developed through Beta 0.9.11.

- **OpenRouter and local execution:** configure a protected API key, discover supported models and run API chats without a provider browser. The provider-generic harness uses existing local Core tools, code mode, commands, plugins, skills and managed workers. Existing browser-provider chats keep their own provider and conversation identity.
- **Permissions and authorization:** explicit user grants reach the common permission owner before task preparation and apply to current workers. Effective capability settings and exact task credentials remain authoritative across recovery and compaction. Compaction does not create, remove or broaden permission grants.
- **Steering and progress:** steer API work at the next safe boundary while retaining running tool processes. See public progress, commands, tool results and background tasks. Earlier topic titles and distinct preparation/provider-acceptance status make chat state clearer.
- **Long-task recovery:** retry transient inference failures without replaying tools. Retain completed terminal results, acknowledge their exact delivered output and release completed execution slots. Use model-aware completion budgets and bounded output-limit continuation. Larger local request/history bounds and cached model discovery remove avoidable delays and request failures.
- **Compact & Resume:** archive original API context before replacing working history with a verified handoff. Compact automatically at safe boundaries or use Desktop's Compact context control. Keep recent complete tool exchanges, first/latest user constraints, fresh unacknowledged output and existing task/process ownership. The Desktop workflow card shows archive, summary, retry, save and actual request-accepted resume stages. Empty, truncated, oversized or tool-bearing summaries receive bounded recovery; summary tools never execute. Failed compaction retains original working history.
- **Claude and workspace repairs:** preserve the exact question with native media, retain upload drafts through editor remounts, recognize exact manually sent drafts and reconcile delayed delivery evidence. Keep OneCode transport context out of the displayed user question. Discover the sidebar browser before a user opens it manually, and present the actual running website. Keep Setup provider selection, Back/Next and Back to chats reachable.

API calls use the selected provider/model's normal pricing and capabilities. API attachments and Goal stages remain unavailable. API steering is applied between inference/tool steps; this release does not claim provider-side live inference steering. Automatic API recovery also applies to Remote-originated sends through the shared main-process harness; the new compaction card and manual control are Desktop features. Original history is retained locally, and uncertain actions are never replayed merely to hide an error. Process retention covers compaction during the running app, not an application update/restart.

Complete Windows x64 and Linux x64 AppImage/DEB artifacts are included for fresh installs. Compatible Stable installations can use cumulative application capsules over the verified Windows 0.5.9 and Linux 0.8.2 bases. Stable and Beta installations, profiles, connector identities and update feeds remain separate. No Beta profile or credential is copied into Stable. See [validation and release receipts](../release-acceptance/v0.9.0.md).
