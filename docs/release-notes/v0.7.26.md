# OneCode Beta 0.7.26

This Beta fixes the false stale selected-chat readiness warning that could remain visible after the selected ChatGPT conversation had already accepted a Send:

- An exact durable native Send acknowledgement now promotes readiness for the same selected session, conversation and browser, even if an earlier selection probe timed out.
- A browser different from the one already assigned to the selection cannot satisfy that readiness state; an unassigned selection may adopt the browser that proved the exact successful Send.
- ACK-derived readiness is published before the existing session-change notification, preventing the renderer from racing ahead with the older terminal refusal.
- A terminal one-minute refusal is reconciled after later canonical activity through a read-only readiness check. The recovery path does not reopen, focus, reload or resend the provider tab.

This remains a Beta candidate until Windows native acceptance proves the former one-minute warning clears after an exact successful Send without reselecting the chat, opening a second provider tab or resending the message. Stable promotion remains blocked until that acceptance passes.
