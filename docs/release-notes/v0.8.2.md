# OneCode 0.8.2

Urgent setup-preservation repair. This source is being built for Stable; publication and artifact verification are recorded in [acceptance](../release-acceptance/v0.8.2.md).

- Acquire Linux's single-instance lock before reading or changing application-layer rollback receipts. Opening the shortcut joins the running application; it cannot leave a false failed-startup marker or roll a healthy updated application back to its older base.
- Bind Linux desktop identity to the installed desktop entry. Repair only existing launchers for the same verified executable, preserve their arguments and other applications, and migrate the legacy OneCode dock favourite without changing its position.
- Recover saved browser/provider preferences from a valid settings backup when native logs prove that an older application reset settings written by a newer version. Preserve the current settings before recovery and remember the backup digest so a later deliberate preference change stays changed. Restore original access only from an untouched conservative recovery state; preserve later access changes.
- Retain exact-provider, exact-route connector evidence across restart. Previously served requests and tools count alongside installed-plugin observations. Unknown evidence offers verification of an existing connector, rather than asserting that it must be created again. Credentials and provider connector records are not rotated or recreated.

Linux requires a complete package once because the repaired bootstrap is part of its immutable runtime. AppImage installations can obtain that package through the internal updater. Full DEB/native replacement remains package-manager-owned. Windows retains the compatible application-capsule path where packaging verification confirms its existing base.

No production installation, restart, settings repair or shortcut change was performed on the maintainer's Ubuntu host. The update is intended for manual installation and verification there.
