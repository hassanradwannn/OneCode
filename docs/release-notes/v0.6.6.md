# OneCode 0.6.6 Beta candidate

This candidate includes the 0.6.4 and 0.6.5 recovery, Stop/restart, startup, recorded file-link and centered-preview fixes. It also addresses a cross-OS connection failure reproduced during Windows/WSL restart acceptance.

When the Windows app closed, WSL forwarded its Linux loopback listener into Windows. A Windows Companion could then discover and silently pair with Linux beta, causing the wrong installation to receive native conversation observations. The Companion now compares native browser-runtime platform metadata with the app's host platform before choosing a bridge. A foreign host cannot clear its saved credential, latch its Disconnect state or receive pairing/observation requests.

The server independently refuses declared foreign-OS pairing and authenticated HTTP actions, covering a listener change after discovery. These checks add a routing boundary; they do not replace origin restrictions, bearer authentication, provider identity, task grants or exact native receipts. Native platform lookup is bounded and retried after transient failure. The built-in browser obtains its OS from the app's service-worker preload. The current Companion requires positive matching platform evidence; the app retains older-client upgrade access so its shipped Companion can replace them.

Native Windows/Linux, ChatGPT/Gemini and Desktop/Remote acceptance remains pending. This reproduced connection failure does not prove the cause of the reported overnight Windows crash. Stable promotion remains gated on acceptance. The Experimental local API remains opt-in, authenticated and loopback-only. Full releases and compatible application capsules are built on GitHub from the frozen candidate source.
