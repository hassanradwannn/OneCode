# OneCode 0.8.6

Recover accepted continuations without leaving their task authorization waiting on a lost browser acknowledgement.

- Recognize ChatGPT's native **Your account changed. Send your message again** card during an owned fresh opening and click its exact Retry once. If Retry continues the chat, wait for its native receipt. If it returns Home with the original task in the composer, verify the complete unchanged draft and selected model before reserving one Send with the same credential.
- Keep Retry inside the original paired browser, tab, document and input claim. Changed drafts/questions, another document, attachments, approvals, cancellation, expiry and an already-started native Send stop the fallback. Repeated failures do not earn another Retry.
- Reconcile a missing Send acknowledgement when the same paired browser records the exact native question and complete app-authored task, including its original credential. The existing outbox commits the receipt; no message or tool call is resent.
- Retain the original permission, provider, session, question and generation checks. A changed task, another browser, explicit cancellation, blocked chat or missing grant cannot supply recovery proof.
- Refresh a silent broken page instead of reporting it as preserved and leaving Continue in that same failed document. Keep the one-shot reload receipt through replacement readiness and history rate limits.
- Consolidate live and recovered input receipts in one commit path, remove redundant readiness handling and simplify an unreachable authorization-guidance branch.

This cumulative Stable application hotfix retains the compatible Windows 0.5.9 and Linux 0.8.2 complete bases. Native runtime components are unchanged. Fresh installations can use the complete [0.8.4 release](https://github.com/hassanradwannn/OneCode/releases/tag/v0.8.4) and update normally.
