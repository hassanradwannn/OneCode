# OneCode 0.8.8

Repair Claude attachment preparation and retain the unsent prompt when an upload cannot be confirmed.

- Find the unique native file input inside the current editor's nearest form or dock. Fresh `/new` pages do not have to use an existing chat's bottom-input ID and dock layout.
- Keep the native file input's exact label, schema, composer ownership, draft lease and upload-state proof. Ambiguous or unrelated uploaders remain refused. Files are handed to the native input once; an uncertain upload is never replayed automatically.
- Preserve Claude's unsent prompt when attachment preparation fails, alongside any staged native file or error. The former failure cleanup could clear the text immediately after telling the user to check the unsent draft.
- Continue to require exact uploaded names, settled native state, zero placeholders, attachment tokens, live permission and native message acknowledgement before claiming delivery.

Complete Windows x64 and Linux x64 installers and compatible cumulative capsules ship together. Existing compatible Windows 0.5.9 and Linux 0.8.2 native bases remain supported. Bridge protocol 22 is unchanged; recorder revision 127 replaces the loaded adapter/content pair. See the [verification scope](../release-acceptance/v0.8.8.md).
