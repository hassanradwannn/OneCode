# OneCode 0.3.5

Tailscale connection checks now race each complete public DNS-to-HTTPS path. A slow IPv4 or IPv6 DNS response no longer delays a working route in the other family. A fast DNS answer alone does not prove readiness: OneCode still requires verified TLS and metadata for the exact connector, and still rechecks native route custody before reporting Connected.

Independent read-only Tailscale daemon queries run together, reducing repeated Windows CLI startup delays. Route changes remain ordered and custody-checked. Privacy-safe startup timings identify CLI, native-route and public-readiness delays without logging connector URLs, credentials or daemon output. This addresses avoidable waits; an offline device, network failure or unpublished public DNS can still delay connection.

Companion fallback messages and settings labels now consistently say OneCode. Shared completion and stalled-turn notices use provider wording. The four previously reported compaction copy/status test failures are resolved. The recorder-grace regression now checks both successful native acceptance and an ambiguous click, with exactly one Send in either case.

The displayed release is **0.3.5**. Its Windows, Companion and updater compatibility version is **0.3.500**, numerically above the previously shipped **0.3.405**. Windows x64 users can update from inside OneCode. Profiles and saved chat history are preserved. Native dependencies and the Computer use download recipe are unchanged.

The native-source archive contains upstream dependency sources and required patches, not another copy of OneCode's application source or user data.
