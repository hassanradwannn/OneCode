# OneCode 0.3.5

Compact & Resume now reports the successor's exact native question immediately after the accepted Send, avoiding a dependency on a later scan that can be waiting for the successor's first tool. ChatGPT's resume prompt carries authorization for the original durable session and exact new conversation. Both providers re-observe the successor after releasing the history gate, so a fast completed response does not remain Thinking.

An unsent first prompt refreshes its local authorization when preparation moves to a replacement document or the app restarts. Authored text and attachments are preserved, and uncertain sends are never replayed. Initial tool authorization now shares the Companion's bounded native Send-receipt wait instead of failing after twelve seconds while the browser is still confirming delivery.

Both adapters publish the first turn from its exact desktop Send acknowledgement even when the provider displays the prompt with Markdown escapes. This fixes a delivered ChatGPT attachment task remaining without a recorded turn and then rejecting its first tool call.

ChatGPT can rename a repeated upload before its file tile first appears, such as `report.txt` becoming `report(1).txt`. Companion now accepts a unique collision rename within the unchanged upload's new native controls. Extra files, changed drafts and unrelated names remain rejected. This prevents a completed upload waiting until the attachment-confirmation timeout.

The native click and form submission retain one Send receipt even if ChatGPT clears the text before removing its attachment tile. The current shell's nested search-unit question is also recognized. Fresh commands can use their exact native Send receipt before that question renders; the accepted question is recorded before its turn so a resumed tool cannot inherit the source chat's last question.

Nested legacy and current question wrappers no longer make the same native question look ambiguous. This restores completion recognition for existing ChatGPT chats and short text replies that otherwise retained the Thinking state after the provider finished.

Compaction can wait briefly for its exact source page to finish loading before a checkpoint reaches the app. Only an explicitly unforwarded loading refusal is retried. The progress display says Preparing until the source dispatch exists. Completed chats stop showing Active even when a recovery watch remains while final history records; newer turns and running tools still show their own activity. These lifecycle rules are shared by both current providers.

Tailscale connection checks now race each complete public DNS-to-HTTPS path. A slow IPv4 or IPv6 DNS response no longer delays a working route in the other family. A fast DNS answer alone does not prove readiness: OneCode still requires verified TLS and metadata for the exact connector, and still rechecks native route custody before reporting Connected.

Independent read-only Tailscale daemon queries run together, reducing repeated Windows CLI startup delays. Route changes remain ordered and custody-checked. Privacy-safe startup timings identify CLI, native-route and public-readiness delays without logging connector URLs, credentials or daemon output. This addresses avoidable waits; an offline device, network failure or unpublished public DNS can still delay connection.

Companion fallback messages and settings labels now consistently say OneCode. Shared completion and stalled-turn notices use provider wording. The four previously reported compaction copy/status test failures are resolved. The recorder-grace regression now checks both successful native acceptance and an ambiguous click, with exactly one Send in either case.

The displayed release is **0.3.5**. Its Windows, Companion and updater compatibility version is **0.3.500**, numerically above the previously shipped **0.3.405**. Windows x64 users can update from inside OneCode. Profiles and saved chat history are preserved. Native dependencies and the Computer use download recipe are unchanged.

The native-source archive contains upstream dependency sources and required patches, not another copy of OneCode's application source or user data.
