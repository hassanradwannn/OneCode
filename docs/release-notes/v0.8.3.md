# OneCode 0.8.3

Stable 0.8.3 is a synchronization and fresh-chat reliability hotfix. It carries the verified Linux launcher-identity follow-up from 0.8.2 and repairs the reported long-chat, reconnect, model-selection, Steer, rendering and task-pane failures without weakening OneCode's exact task, model or Send ownership rules.

- **Complete long-chat import.** ChatGPT's native Fiber bridge now pages bounded older mounted turn groups instead of rereading only the newest six forever. The page recorder also no longer clips a native observation at 400 KiB before durable custody: it enforces the transport ceiling against the real serialized payload, drops optional rendered HTML before canonical prose, and preserves long UTF-8 provider output whenever it fits the safe 1.5 MiB observation budget.
- **Reconnect and Compact & Resume recover cleanly.** A browser reload is no longer treated as a completed repair merely because Chrome accepted the reload request. Recovery waits for a newly registered replacement document to prove the same conversation is ready before Compact/Resume or follow-up delivery advances, and a rejected reload cannot leave a stale readiness receipt waiting forever.
- **Fresh-chat model identity survives provider ID churn.** OneCode freezes the provider-observed display identity beside the exact requested native model ID. ChatGPT, Gemini and Claude still prefer the exact ID and still require native selection proof; only a unique, currently observed matching label may recover a model whose opaque provider ID changed before the fresh chat opened. Ambiguous, denied or genuinely different models remain refused.
- **Steer stays where it was inserted.** Steering retains an exact viewport anchor at its insertion boundary instead of inheriting an absolute top/end follow-output position. The navigation repair is presentation-only; Steer's durable turn, Stop and Send/ACK ownership are unchanged.
- **Provider code blocks stay code blocks.** Shared native HTML-to-Markdown capture recognizes block code even when a provider omits the traditional `<pre>` wrapper, while refusing to swallow adjacent explanatory prose into the code fence.
- **OneCode-branded connection state.** The sidebar connection control always shows the OneCode mark, with a smaller connected/connecting/offline/error badge driven by the existing canonical connection state and accessible status text.
- **Linux dock identity follow-up.** The canonical launcher repair from commit `6af893e` retires the legacy GNOME application identity only after preserving an existing favourite, so OneCode can stay pinned without creating a duplicate window identity.

Steer retains its native Send receipt until delivery acknowledgement, so an early transcript observation cannot consume the receipt needed for the next Steer. Ordered native history carries an exact later-question anchor; importing older questions no longer replaces the active task merely because those rows receive newer journal sequences. Superseded credentials, changed questions and foreign documents remain refused.

The Companion protocol moves to 22 for frozen model-display identity and ordered native-history metadata, and the recorder moves to 118 with Fiber helper 35 for progressive long-chat import and Steer receipt custody. Older loaded Companions are required to reload instead of silently ignoring these contracts.

0.8.3 is built as synchronized Windows x64 and Linux x64 complete artifacts plus backward-compatible application capsules when the verified native runtime matches. Windows retains the verified 0.5.9 compatible base; Linux targets the verified 0.8.2 complete base, subject to final frozen-candidate runtime comparison in the release verification record. Full DEB/native replacement remains package-manager-owned when a complete package is required.
