# OneCode 0.6.4 Beta candidate

This candidate targets recovery, Stop/steering, idle browser startup, recorded file links and image previews. Stable promotion remains pending native Beta acceptance.

- Recovery reads the current exact chat's running-tool count before granting a refresh. A stale busy snapshot no longer holds a repair indefinitely; an unavailable tool-state response still refuses the action.
- The connector's 65-second startup budget includes the initial connection lifecycle. Late startup completion cannot open the expired input's browser tab.
- Concurrent explicit sends still share a browser startup. A later queued Send may wake the configured browser again after an unanswered successful launch has aged out. Native Send retains its original outbox claim and receipt checks.
- Stop can use the exact redeemed native question receipt during initial thinking before the provider mounts an assistant section. A click acknowledgement still does not prove termination.
- A trusted desktop click on a recorded provider file link can dispatch its native control without granting model screen/control authority or attaching a debugger. Exact session/message membership and one-shot delivery still apply.
- Image preview dialogs are centered in the app window.

The Experimental local API and existing provider/session, permissions, task capabilities and update-channel isolation are retained. No change removes immutable runtime compatibility checks. Normal release delivery includes complete Windows/Linux bases and compatible application capsules built on GitHub from the frozen source.

The reported overnight crash has not yet been attributed to a confirmed exception. Startup regressions reproduce two indefinite-wait conditions, but those alone do not prove the cause of the reported crash. Native Windows/Linux, ChatGPT/Gemini and Desktop/Remote acceptance must be recorded separately before stable promotion.
