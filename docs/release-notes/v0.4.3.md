# OneCode 0.4.3

Public connection checks now allow a slow but valid HTTPS or MCP reply to complete. Earlier checks stopped each request after four seconds, causing healthy connections to remain Checking or alternate between Connected and failure. DNS checks still race independently, and a new timeout result distinguishes a slow response from a TLS failure. Only exact metadata and a valid MCP initialize reply establish Connected.

Windows installations can install 0.4.3 through **Settings → General → Check for updates → Install when done**. This release includes the full installer needed to enable the new application hotfix path on older installations.

After 0.4.3, compatible hotfix releases can carry a smaller application bundle instead of another complete installer. The internal updater verifies the release checksums, architecture, native runtime fingerprint and every application file. Install when done waits for active work, closes OneCode, applies the bundle and verifies the reopened application's version and visible window. The matching Companion activates through its existing idle reload path. This is a coordinated restart, not replacement of code inside an active chat.

Failed file replacement or a crashed launch restores the saved application files when no successor is running. A running but unconfirmed successor is never terminated or overwritten; its backup and diagnostic remain available. Native runtime changes use a full installer when one is published. Profiles, credentials, connector URLs and chats are outside the hotfix payload.
