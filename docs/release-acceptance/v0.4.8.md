# OneCode 0.4.8 acceptance

## Evidence and repairs

The delivery record for the reported Continue contained no steering target. The previous turn remained open until a native manual Stop, after which the same queued input sent. Activity expiry had removed the target from the control projection. A real Chromium renderer fixture reproduces the missing target; a backend regression reproduces Stop rejecting that same unresolved turn as active_turn_changed.

The controls owner now exposes the durable unfinished turn separately from the expiring Working presentation. Explicit immediate input keeps that target, while after-turn, plan and tool-injection choices keep their own behavior. Stop rechecks the durable conversation/turn and supersession; native redemption still proves the exact current page/question. A click ACK cannot manufacture a turn end or release the input. Restarted historical turns are not presented as Working.

The folder-inspection calls in the connection report completed locally, several after about 30 seconds; intermittent public TLS check failures were also logged. No authorization rejection was established for that report. A separate modern-protocol regression proves that a long tool exchange emitted no bytes before completion. Tool exchanges now stream ten-second keepalive comments, while discovery retains its format. Both protocol eras were tested through the actual Funnel relay with the result held back: keepalive bytes arrived, then exactly one result from one execution. A truncated upstream stream closes as a downstream interruption without replay. Premature MCP response closure records only the surface and elapsed time.

## Validation

- Six affected backend files: **1,224 passed, zero failed, six existing skipped desktop-schema cases**. This comprises 700 bridge checks and 524 checks across MCP, input delivery/startup and Funnel relay/integration; it is not a whole-repository suite claim. The six skips are retained existing fixture conditions, not newly disabled cases.
- Three failure controls were observed before their repairs: missing renderer steering target, rejected expired Stop and no bytes from a pending modern exchange. The local Stop fixture was corrected to use its real request helper and a unique conversation; the existing image fixture now explicitly selects Inject before expecting tool delivery. Production behavior was not weakened for these fixture corrections.
- Real Chromium production renderer: 19 checks passed, including expired-activity steering, empty/repeated submissions, captured Stop, queue editing/history and explicit image injection. What's new passed dark/light current highlights, exact installed-version notes, Settings reopen, same-version suppression and modal deferral, with retained older-pane coverage.
- Public privacy/history, notices, TypeScript and production builds passed. Windows x64 packaging/resource isolation and packaged native smoke passed: Electron 44.3.0, MCP, Sharp 0.35.4/libvips 8.18.6, PTY, tree-sitter and Pets. Dependencies are unchanged.
- The unmodified capsule staged twice under Electron and activated through the production updater helper from an isolated 0.4.7 copy to 0.4.8. The actual application version, stable loaded visible window, three current highlights, seen-state persistence, quiet same-version restart, Settings reopening and unchanged native inventory were verified. Registration/shortcuts were mocked for that unregistered copy; login/protocol calls were stubbed in memory before exact application entry. Normal Windows startup registration was identical before/after; the user's installation and profile were not patched by QA.
