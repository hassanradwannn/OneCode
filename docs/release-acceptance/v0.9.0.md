# OneCode 0.9.0 — Stable validation record

On November 6, 2026, the user authorized promoting all accumulated fixes to Stable 0.9.0 and publishing it. This supersedes the earlier Stable freeze/publication hold. The candidate contains the full Beta integration through published Beta 0.9.11, with Stable version metadata and release documentation. Runtime implementation is retained from the tested Beta source; channel-specific packaging uses the existing Stable owner.

The full integration descends from Stable 0.8.9 (`ca9bedf630084d976624fcd0c4cc6f3a1284f7d8`) and includes the API harness, permission/task-binding repairs, steering/progress, terminal receipt recovery, output/request budgeting, Claude uploads/draft reconciliation, topic naming, sidebar browsing, Setup navigation and archived API context compaction. Published Beta tags remain immutable. The unrelated dirty/staged work in the canonical checkout is excluded from the release commits.

## Validation scope

The preceding [Beta 0.9.11 record](beta-v0.9.11.md) includes 409 affected-owner cases, 19 selected actual-renderer cases, public verification and both platform package/smoke checks. Earlier Beta records cover the accumulated fixes. Promotion checks, platform receipts and publication evidence are recorded below when complete.

Promotion validation passed **599 distinct local cases**: 564 across 19 API/provider, permission, outbox, terminal, native task-binding, code-mode, context and version suites; 17 Setup cases; and 18 selected actual-renderer cases covering native/API compaction, live tools/background work, recovery, provider controls and pre-Send status. One existing code-mode case is skipped. Renderer cases outside the selection are filtered and not claimed passing.

The first promotion run exposed three stale local fixtures: provider discovery expected only browser providers; an API progress case expected the now-supported Compact control hidden; and an extracted update-summary fixture omitted its current provider-readiness dependency. The fixtures were corrected to assert the shipped contracts, and the affected cases passed again. No runtime behavior was weakened to satisfy them. Tests remain ignored/local under repository policy.

Final public verification passed source privacy/history, third-party/native notices, TypeScript and Desktop/Remote production builds. Existing bundle-size warnings remain. The application implementation matches Beta 0.9.11; promotion changes only aligned version owners, Stable What's New and release documentation.

The legacy bridge matrix is not certified green: the 0.9.10 audit found 175 failures with exactly the same failure names against the published 0.9.9 module baseline. Those unrelated fixtures are not represented as repaired by this promotion. Real signed-in browser/provider, native Linux, physical Remote and installed-updater acceptance are distinct lanes and remain limited to previously recorded evidence. The user's publication authorization is not reported as a new automated or native test pass.

Stable compatibility uses independently verified published Windows 0.5.9 and Linux 0.8.2 complete-base descriptors and their own runtime fingerprints/checksum registers. Beta bases are not used as Stable compatibility evidence. GitHub must build complete fresh-install artifacts and compatible cumulative capsules from the exact frozen Stable source. No production profile, credential, installation or task process is changed by preparing/publishing this release.
