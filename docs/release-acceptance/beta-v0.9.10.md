# OneCode 0.9.10 Beta — validation record

The reported context-limit interruption exposed a missing API working-context handoff. OneCode previously kept submitting the full API thread until its local budget refused another step. Canonical history and processes were retained, but Continue could hit the same limit. This release adds checkpointed automatic and manual compaction through the existing API session queue.

The compactor verifies a content-addressed original archive before any active swap. Summary calls are bounded, hierarchical, tool-free and current-owner checked; complete parts can be reused after failure. Opaque reasoning metadata is excluded from summary requests and retained in the archive. First/latest user messages and recent complete tool pairs remain literal. Fresh unacknowledged tool output is pinned for full model delivery; an omitted page is not marked received from a handoff summary. Failed, cancelled, truncated, unowned or non-reducing compaction cannot replace active history. Existing task identity, permissions and terminal/worker/browser custody are unchanged.

Automatic handoffs run at safe model/tool boundaries near 72% of estimated model context, and before local message/body guards. Typed upstream context rejection permits at most two inference-context recovery attempts per model step. Transient summary inference retries reuse the existing bounded policy and never dispatch task tools or replay local writes. The automatic-compaction toggle is respected. Manual idle compaction joins the session queue and sends no new user task; live requests wait for a safe boundary. The existing Desktop Compact action routes to this API owner, while native browser compaction retains its existing path. Automatic API recovery runs in the shared main-process harness; this release does not claim a new manual Compact button in Remote.

The context meter derives API working size from the saved API thread, including current system/tool overhead, independently of the full retained canonical transcript. Progress reports handoff preparation and reduction. The context error points to Compact context and a larger model when the exact pinned request cannot fit.

OpenRouter's [documented compression](https://openrouter.ai/docs/guides/features/message-transforms) may remove or truncate middle messages; it is explicitly disabled to keep full-delivery output receipts meaningful. [Typed context errors](https://openrouter.ai/docs/api/reference/errors-and-debugging) are recognized in HTTP, SSE and non-streaming response envelopes without exposing raw provider prose.

Validation is isolated. No user profile, credential, original failed thread, application installation or production task process is changed. Final local, cloud and publication receipts follow below; installed and real-provider acceptance remain pending. Stable remains unfrozen and unpublished.

## Local validation

- 103 affected API/session/client/compactor/budget/recovery/context-meter/error cases passed. These include restoring an already over-limit thread before task dispatch, typed HTTP/SSE/JSON errors, bounded summaries, exact original archives, denied archive writes, invalid/truncated summaries, cancellation/owner changes, cached completed parts, complete tool-pair retention and opaque-reasoning exclusion. Final manual success/cancellation cases passed again after the cancellation UI-error refinement.
- A real local server process remained alive while its single API turn compacted between subsequent file-reading tool steps. It launched once, retained the same process/session custody and finished the task without replaying a tool. Manual idle compaction recorded no new user input, turn or tool call.
- Three actual-renderer API cases passed: live recovery/steering, pre-ACK send phases, and manual compaction/cancellation with the reduced context estimate. An isolated hidden Electron capture with the actual renderer/CSS verifies Compact context, its busy/cancel state, reduced 24K/128K estimate and visible manual-compaction progress. Native fonts are not staged in that source-CSS capture; it is layout/control evidence, not installed-app acceptance.
- 48 terminal-spool/call-context/Remote-action cases and 52 code-mode/output-budget/Stop-ownership cases passed. One existing harness case remains skipped. Terminal coverage retains 1,000 unread results and the real 64/65 process-capacity gate.
- The broader legacy bridge suite is **not green**: 561 cases passed and 175 failed. An isolated transform of every changed tracked source module back to the published `beta-v0.9.9` bytes produced exactly the same 561 passes and 175 failure names, with no candidate-only failures. Three representative failures were also independently reproduced against that baseline. This does not certify the legacy native bridge matrix; its existing failures remain separate work.
- Across these runs, 767 distinct cases passed; overlapping reruns are counted once. Final public verification passed after the last application change: source privacy/history, notices/native references, TypeScript, Desktop and Remote production bundles. Existing chunk-size warnings remain.
