# OneCode 0.8.9 acceptance

Scope: explicit user path grants and Remote provider-file link handling.

The existing written folder parser required a short standalone approval declaration and rejected a native path followed by a multiline task. Regression tests reproduce that refusal for an existing folder and an explicitly quoted file. The updated parser accepts existing native path lines, terminal path directives, quoted paths in task directives and legacy explicit grants. Fenced/indented code, blockquotes, quoted document prose, negation/conditions, whole drives, relative paths, traversal, alternate data streams and unsupported network hosts do not become grants. Missing paths cannot approve guessed parents.

The existing root owner persists grants before Desktop/Remote message preparation. A file uses an optional `kind:file` root marker enforced by the shared resolver; it covers only the exact canonical file and refuses children, parents, siblings, link changes or replacement by a directory. It survives config reload and cannot become a learned/default command workspace. Explicit containing folders retain earlier virtual aliases. Existing capabilities/read-only state are retained. Trusted user objectives may supply paths; generated plan stages and attachment contents cannot. Duplicate input IDs do not reapply a revoked grant. Provider/task binding and permission admission remain separate.

The Remote screenshot's saved reply contains a ChatGPT `sandbox:/mnt/data/...pdf` link preceded by an inline content-reference marker. Remote previously removed the private scheme from its href, leaving styled text with no working destination. The new authenticated resolver verifies exact recorded assistant-message membership and returns that session's native ChatGPT URL. Desktop's existing native file action uses the same membership owner. Remote opens the source chat on the phone, retains the native account's download control, provides a blocked-popup fallback and reports failures visibly. It does not transfer provider-private file bytes or disclose a signed file URL. Inline reference syntax is hidden outside literal code.

Focused automated checks cover canonical path resolution, exact-file scope, settings reload, changed file kind, trusted Desktop and all-provider Remote submission order, generated-stage exclusion, duplicate revocation, file-message membership, Remote origin/authentication, external link isolation, popup blocking and literal code. Final regression/public build and cloud receipts follow below. Tests remain local and ignored under repository policy.

The final local selection passed **1,267 checks across 18 suites**, including the full Desktop IPC suite, root approval, sandbox, config, workspace, skills, provider-file membership, Remote actions/transcript/HTTP/history/pending inputs, bridge, Gemini/Claude task binding, opening input, kernel workspace and version alignment. Ten existing platform-dependent sandbox checks were skipped; they are not passes. Both new path-grant reproductions failed against the prior implementation before the repair. Public `npm run verify` passed privacy/history, notices, TypeScript and Desktop/Remote production builds.

Signed-in native Windows/Linux and physical-phone acceptance of the new build remain pending. The CUA Driver authorization host has been unavailable; no substitute native driver, credential copy or permission bypass is used. No production update/restart, task replay or modification of the user's current grant configuration is performed as part of publication.

GitHub builds complete Windows/Linux artifacts and compatible capsules from one frozen source via `stable-release`. Windows 0.5.9 and Linux 0.8.2 remain the verified capsule bases. Bridge protocol 22, recorder 127 and native runtime components are unchanged. No Native-Sources archive is attached. Unrelated staged documents and private Graphify/profile evidence remain outside this release's source commit.
