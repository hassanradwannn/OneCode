# OneCode 0.8.2 verification

Status: unpublished build candidate. Published 0.8.1 assets and tag remain immutable. Ubuntu remains unchanged for the maintainer's manual update and verification.

## Reproduced failure

Linux logs showed a ready 0.8.0 application refusing a staged update because its application-layer startup marker still existed. The next launch interpreted that marker as a failed startup, rolled back to bundled 0.5.10 and reset a newer settings file. Its original was retained in a timestamped unreadable-settings backup. Subsequent launches reached 0.8.1, but the reset had changed the browser/provider from Brave/Claude to Chrome/Gemini.

The immutable bootstrap inspected rollback state before the mutable application acquired its single-instance lock. An isolated regression against frozen 0.8.1 reproduced both defects: a secondary launch created a marker over a ready primary, or changed active/rollback receipts while a primary was starting. The repaired source refuses the secondary before any application-layer mutation or application entry is loaded.

Setup also ignored saved request/tool-use evidence when deciding whether a connector existed. The connection owner already scopes that evidence to the exact provider, profile and verified public route. Rendering now uses that existing scoped evidence; changed routes and explicit removal still invalidate it.

## Validation

264 focused checks passed across 16 local suites covering configuration, settings recovery, exact-route connector proof, secondary bootstrap, native Electron ASAR execution, launcher repair, profile ownership and updater handoff. The secondary-launch cases failed against frozen 0.8.1 and pass with the repaired bootstrap. Public verification passed privacy, notices, TypeScript, Desktop and Remote builds.

An additional regression used a private, read-only copy of the maintainer's actual saved Linux config, pre-reset backup and matching log lines. It restored the saved Brave/Claude selections while preserving the current roots, capability flags, read-only choice and tunnel settings. The source Ubuntu files were not changed.

Matching Windows/Linux package builds, smoke, runtime fingerprints, checksums and publication receipts will be recorded after completion. Windows targets the compatible 0.5.9 base. Linux's changed immutable bootstrap requires a new complete 0.8.2 base; its older AppImage updater will select the full-image route rather than attempting a capsule against the old loader.

Recovery requires a currently valid saved configuration plus native reset/downgrade evidence and a valid pre-downgrade backup. Missing, malformed, future-version or unrelated backups do not authorize restoration. Later nondefault preferences and access reductions are retained. The original backup is never modified; the current file is backed up before recovered settings are committed.

Native production Ubuntu installation and post-update verification are reserved for the maintainer. Read-only diagnostics were used; no live config, shortcut, service or application was changed by this work.
