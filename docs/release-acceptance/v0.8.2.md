# OneCode 0.8.2 verification

Status: [published Stable 0.8.2](https://github.com/hassanradwannn/OneCode/releases/tag/v0.8.2), frozen source/tag `e52fb29f7344d77ccfaa619c32a4b0619656b243`. Later documentation commits do not move the tag. Published 0.8.1 assets and tag remain immutable. Ubuntu remains unchanged for the maintainer's manual update and verification.

## Reproduced failure

Linux logs showed a ready 0.8.0 application refusing a staged update because its application-layer startup marker still existed. The next launch interpreted that marker as a failed startup, rolled back to bundled 0.5.10 and reset a newer settings file. Its original was retained in a timestamped unreadable-settings backup. Subsequent launches reached 0.8.1, but the reset had changed the browser/provider from Brave/Claude to Chrome/Gemini.

The immutable bootstrap inspected rollback state before the mutable application acquired its single-instance lock. An isolated regression against frozen 0.8.1 reproduced both defects: a secondary launch created a marker over a ready primary, or changed active/rollback receipts while a primary was starting. The repaired source refuses the secondary before any application-layer mutation or application entry is loaded.

Setup also ignored saved request/tool-use evidence when deciding whether a connector existed. The connection owner already scopes that evidence to the exact provider, profile and verified public route. Rendering now uses that existing scoped evidence; changed routes and explicit removal still invalidate it.

## Validation

265 focused checks passed across 16 local suites covering configuration, settings recovery, exact-route connector proof, secondary bootstrap, native Electron ASAR execution, launcher repair, profile ownership and updater handoff. The secondary-launch cases failed against frozen 0.8.1 and pass with the repaired bootstrap. A full-update regression verifies that a Linux release with a changed immutable loader selects its complete AppImage, even when an old startup marker exists. Public verification passed privacy, notices, TypeScript, Desktop and Remote builds.

An additional regression used a private, read-only copy of the maintainer's actual saved Linux config, pre-reset backup and matching log lines. It restored the saved Brave/Claude selections while preserving the current roots, capability flags, read-only choice and tunnel settings. The source Ubuntu files were not changed.

An additional real Electron multi-process check passed: secondary launches against both a starting and a ready primary left its active/startup receipts unchanged. This brings the exercised local total to 266 checks across 17 suites. It is separate from the requested manual production Ubuntu verification.

Both frozen-source GitHub builds passed public verification, packaging, packaged runtime smoke and canonical checksum finalization: [Linux 40981530458](https://github.com/hassanradwannn/OneCode/actions/runs/40981530458) and [Windows 40981532942](https://github.com/hassanradwannn/OneCode/actions/runs/40981532942). All 21 curated assets match the canonical register's 18 payload entries and the platform registers; no native-source archive was uploaded. Both downloaded application archives and every contained file matched their manifests. Companion version/name 0.8.2 and stamp `fbfae46d41b5` matched source; recorder 116, native helper 8 and protocol 21 remain unchanged.

Windows retains the compatible 0.5.9 base and runtime `0eadd65d501dc6b2f89f08de2bbbeeccc83974d600ab62611412ab0ff340daa4`. Its capsule is 34,815,404 bytes, SHA-256 `da163c724bd3961432673c53d49564d484501e35a8673a04bd57a120cfb64d78`.

Linux's changed immutable bootstrap requires complete base 0.8.2, runtime `63f9d4c3fbd694b217fabcccb5de917379bf0592be4486a162aade8d59ca9180`. Its complete AppImage is 266,613,535 bytes, SHA-256 `c3cccba882355c64fa99e5ebc22f44dbd8d2cfc3a25e378793eb372024d0bd6d`; the 34,807,076-byte capsule is bound to that new base. Older AppImage installations select the full-image route rather than applying that capsule against the old loader. Full DEB/native replacement remains package-manager-owned.

The private graph receipt records frozen-source hashes, stamp and parser limitations. It preserves prior document semantics and is navigation evidence, not proof of production installation.

Recovery requires a currently valid saved configuration plus native reset/downgrade evidence and a valid pre-downgrade backup. Missing, malformed, future-version or unrelated backups do not authorize restoration. Later nondefault preferences and access reductions are retained. The original backup is never modified; the current file is backed up before recovered settings are committed.

Native production Ubuntu installation and post-update verification are reserved for the maintainer. Read-only diagnostics were used; no live config, shortcut, service or application was changed by this work.

## Post-publication follow-up — 2026-10-30

The maintainer subsequently reported that the manual internal update completed with visible progress, but OneCode could not stay pinned to Ubuntu's dock. Native inspection found GNOME Shell 42.9 and two owned desktop entries sharing `StartupWMClass=io.onecode`. The legacy entry was `NoDisplay=true`; GNOME 42 still indexes that entry and can select it first. Its matching algorithm does not prefer the visible entry or strip the desktop suffix for that tie-break. See [GNOME 42.9's matching owner](https://github.com/GNOME/gnome-shell/blob/42.9/src/shell-app-system.c#L87-L114).

At the maintainer's new request, only the launcher was repaired on Ubuntu: the legacy alias now has `Hidden=true` and no window-class claim, and the visible canonical entry is pinned. Other favourites were preserved. Native CUA inspection showed OneCode's dock menu offering **Remove from Favorites**. The same app process continued running; configuration, connector proof and active-layer files were unchanged. No application update or restart was performed by the agent.

The corresponding mutable launcher-owner repair is prepared for the next update. It migrates any existing favourite before retiring its alias, preserves an alias when migration fails, and handles GNOME's typed empty favourites list. This follow-up is not part of the immutable published 0.8.2 tag or assets. See [next-update handoff](../NEXT-UPDATE-HANDOFF.md).
