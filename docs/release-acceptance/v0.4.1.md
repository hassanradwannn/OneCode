# OneCode 0.4.1 acceptance

Windows x64 patch validation on 2026-10-21. Application, Windows installer, Companion and updater metadata use version **0.4.1**. No dependencies or bridge protocols changed.

## Reproduced failure and live validation

SSH diagnostics on the affected Windows laptop established that Tailscale was running, signed in and healthy. Cloudflare DNS over HTTPS returned valid public Funnel ingress addresses. Google DNS over HTTPS timed out on the laptop's hotspot connection.

The exact OneCode 0.4.0 Node HTTPS request to Cloudflare returned HTTP 400 with its combined Accept header. The corrected request returned HTTP 200 with DNS JSON on that same laptop. The fix uses Cloudflare's required `application/dns-json` request media type and accepts both `application/dns-json` and `application/json` responses.

The corrected source checker then verified the laptop's exact existing connector through public DNS, certificate-validated HTTPS, exact protected-resource metadata and MCP initialization three times: **3,295 ms, 2,342 ms and 3,110 ms**. This ran as a standalone diagnostic using the laptop's existing bundled Node runtime; OneCode itself was not installed, replaced or restarted. No system DNS, firewall, Tailscale account or route settings were changed. Temporary diagnostic files and the CUA observation session were removed afterward.

Both ChatGPT and Gemini use this shared public checker. Existing address validation, IPv4/IPv6 racing, cancellation, strict TLS, response-size limits, exact metadata identity, MCP handshake checks and route custody remain in force. Private Remote Serve does not use this public DNS path and retains its existing owner.

## Regression and package checks

Focused public DNS, Funnel, startup prerequisites, MCP, relay and tunnel lifecycle coverage passed **152 tests**, with no failures or skips. Added cases reproduce Cloudflare's rejection of a combined Accept header while Google is blocked and verify both resolvers' JSON response media types.

TypeScript, privacy and notice validation passed. Notices cover 167 production packages, eight catalog entries and 730 pinned native source archives/patches.

The complete local suite ran all 468 test files: **10,407 passed, 12 failed and 52 skipped** on its initial run. The release changelog was corrected from 0.4.0 to 0.4.1, and the local packaging assertion now checks the release-note title against the actual version. The plugin process, input-recovery and renderer failures passed focused reruns with reduced worker contention and no production changes. Those reruns passed **98 plugin/packaging tests** (one existing skip), **seven selected input-recovery cases**, and **all 132 renderer-state tests**. Every initially failed case was matched by exact file and test name to a passing rerun; no failing case was skipped to clear publication. The initial full run is retained as a failed run rather than reported as clean.

Fresh public `npm run verify` and packaged Windows x64 runtime smoke checks passed. The smoke check verified Electron 44.3.0, MCP, Sharp 0.35.4/libvips 8.18.6, PTY, tree-sitter and Pets focus bindings. The final application archive contains the corrected DNS checker. Application, installer feed and Companion agree on 0.4.1; Companion build stamp is `56272edf3cae`.

Installer SHA-256: `f2c650fafcf9eb583367e12a8193026458d12a73b3521c275c12273e7071f788` (203,618,182 bytes). All ten uploaded release assets were checked against GitHub's server-computed SHA-256 digests. The large optional native-source archive is excluded; the native inventory is unchanged.

The local Graphify refresh contains 8,581 nodes and 27,865 edges, with no duplicate IDs, dangling edges, self-loops or duplicate edges. ## Limits

This patch was verified on the actual affected laptop network without installing it there, as requested. A post-update app launch and physical cold boot remain for the user's manual update. A standalone connector handshake is not proof that the provider has subsequently invoked a tool. All 0.4.0 feature acceptance is retained in its [separate record](v0.4.0.md); those native workflows were not all repeated for this DNS-only patch.

The fix applies to every updated installation. It cannot guarantee access when both resolvers or the actual Funnel ingress are blocked, or bypass captive portals, account consent, expired credentials or a sleeping host. Saved connector URLs, private Remote routes, permissions and chats are preserved.
