# OneCode 0.4.6 acceptance

Validated on 2026-10-22. Windows x64 application hotfix based on the complete 0.4.5 native runtime. Application and Companion version: 0.4.6. Companion stamp: `31ea0e276417`; paired page-recorder protocol: 67; Fiber protocol remains 31.

The new recorder regression reproduces the accepted-Send gap with five-character and 60,000-character messages before the repair. Both pass after the repair, including exactly one native Send, one local turn and no duplicate turn after the source becomes readable. Existing accepted-Send controls cover rejected ACK, replaced document/receipt and no new generation.

The historical user's message was ACKed with fresh credentials but lacked a turn_start. A deterministic source probe and full content-script DOM tests reproduce the mounted/unreadable-source gap. The precise historical DOM state was unavailable; this is not a claim of a newly performed signed-in provider reproduction.

The fix retains exact native message, conversation, epoch, recent accepted receipt and generation evidence. Local authorization lifetime, Block/Trust and per-input/worker receipts remain unchanged. No automatic Send replay is introduced.

## Results

- All 938 tests in the complete affected content-script and ChatGPT local-binding files passed, with zero failures or skips. These are focused owner suites, not a new whole-repository regression run. The two added regression cases failed against the previous source and pass after the repair.
- Public verification passed: privacy/history, notices, TypeScript and production builds. Windows directory packaging, resource isolation and packaged native runtime smoke passed, including Electron 44.3.0, Sharp 0.35.4/libvips 8.18.6, MCP, PTY, tree-sitter and Pets. Dependency versions are unchanged.
- Real Chromium checked current highlights in both themes and the exact 0.4.6 notes link, alongside existing modal deferral, Settings reopening, same-version suppression, translated and short-window cases. An initial new fixture used the wrong notes-button selector; correcting that fixture yielded a passing run without changing production UI.
- The unmodified release capsule was staged twice under packaged Electron and activated through the production detached helper onto a preserved isolated 0.4.5 installation. Actual application version, stable visible window, three current highlights, persisted seen state, quiet same-version restart, Settings reopening and unchanged native inventory were verified. The original application profile was not used.
- Isolated activation mocked registration/shortcut ownership and stubbed login/protocol changes in process memory before the exact application entry resumed. The user's startup Run entry was compared before/after and remained unchanged. No installer or hotfix was applied to the normal desktop or laptop during acceptance. No new signed-in provider message was sent during this release test.
