A fresh configuration records its own version without an update announcement.

## Exact release payload activation

The unmodified release hotfix ZIP was staged twice under Electron and applied to a preserved isolated copy of the packaged 0.4.3 baseline. The production detached helper verified the new application version and a stable loaded visible window. The actual restarted application showed Version 0.4.4 with four highlights and Settings access. Its existing lastSeenVersion owner persisted 0.4.4 after opening. A second real launch using the same isolated profile did not reopen the pane automatically, and the Settings action reopened the exact installed-version summary.

Every staged application file matched the release manifest after activation, and the native inventory matched before and after. Both test app processes exited. The fixture used a separate profile and random bridge port. Registration/shortcut checks were mocked because the copy was unregistered, and login/protocol registration was stubbed in memory through the debugger before application code resumed. The successful run verified the normal Windows startup registration unchanged. This establishes packaged hotfix activation and pane behavior, not installation on the user's desktop or laptop.
