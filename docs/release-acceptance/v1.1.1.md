# OneCode 1.1.1 acceptance

Candidate verification is in progress. Source, GitHub payloads and installed acceptance are recorded separately.

The reported ChatGPT reply exposed two independent problems: visual snapshots were separate timeline rows, and a long native capture exceeded the original markup budget and fell back to flattened text. The repair retains exact DOM slots with fallbacks, then joins them only to one ready, saved artifact from the same native message and surface. Canonical text and execution/turn ownership are unchanged.

A read-only native inspection through CUA Driver CLI ran the repaired exporter against the uniquely owned public reply. It retained three actual visuals with their established surface identities and a 77,513-character structured capture. Reference popovers/icons were excluded without matching filenames or content. A temporary renderer-only viewer used the production placement, sanitization, formatting, preview and fullscreen code against that capture. It displayed all three visuals in position, fetched only their three saved sources, showed no duplicate visual fallbacks and suppressed five earlier reference false positives. Expand/restore and centered fullscreen were observed. The initial viewer omitted the app's dark theme; the viewer was corrected and code contrast rechecked. No OneCode installation, profile, provider prompt or Beta build was changed for this viewer.

The overlapping six-file local matrix passed 561 tests with one optional skip. The final five-file focused matrix passed 36 tests with one optional skip, including oversized markup, reference-icon exclusion, stable native surface identity, public document links, safe prose emphasis, exact placement across the three browser provider identities, refusal of ambiguous/mismatched slots, legacy source backfill, canonical-text preservation, Core/OpenRouter behavior and Remote control-state retention through unchanged history polling. These counts are not additive. TypeScript and public verification, including production Desktop/Remote builds, passed; final frozen-build verification remains pending.

The older final-identity suite retains 23 failures caused by invalid legacy fixture conversation IDs. An isolated checkout of the preceding published-source branch reproduced the same 23 failing case names and 12 passes. Production identity guards were not weakened to accommodate those fixtures.

The repair uses native position metadata rather than labels, titles or text matching. An explicit native exclusion list identifies old reference false positives; merely missing or unmounted visuals remain available. Unknown placement does not grant authority to invent a source, change chronology or remove unrelated text. Provider-only callbacks and the account limitations documented for 1.1.0 remain unchanged.
