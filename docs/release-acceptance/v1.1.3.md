# OneCode 1.1.3 acceptance

Candidate source verification is complete for the native picker repair; frozen GitHub packaging and payload checks are pending. Source, adapter-level native acceptance, packaged payloads and installed app acceptance are recorded separately.

## Failure and repair

The loaded Companion was confirmed as the published 1.1.2 build. Gemini can append the thinking level to the native model caption, while its primary model span retains the actual model name. Treating the entire caption as the model can reject a valid checked choice. The former reader also constrained secondary captions to one model-row role and relied on trigger toggling to close the thinking submenu.

The repair reads the exact primary native span when available. A combined legacy caption requires the same checked model and an independently observed thinking selection; it is not handled by guessing or stripping familiar words. Both visible model captions are retained across row roles. Thinking rows remain bound to their trigger's exact controlled menu/radio group, with unique checked-state and known-effort validation. Escape closes owned submenus; a legacy fallback rechecks the exact submenu before acting. Original caller, route, editor, draft, attachment and native model checks remain in force.

## Native acceptance

CUA Driver CLI 0.36.0 operated the existing signed-in Brave window. A temporary DevTools source snippet executed the exact repaired picker functions with a bounded DOM-only QA guard for the same route, editor, draft and attachments. No console input, provider-private API or provider Send was used. The snippet's saved content was verified against its generated source before execution.

The native result contained the current-model option and three unlocked model choices with both visible captions and observed Low/Medium/High thinking levels. The locked option was excluded. First and last native model IDs matched; first and last thinking levels were Low, the original caption was restored, the guard remained current and the result reported no error. The tested adapter file SHA-256 was `28cac906926b94bbe5ab90626a86056d6fbf4be941c487fb25050264777fe23a`.

The temporary source snippet was removed through DevTools. The original Flash/Low selection, closed developer tools and browser monitor position were restored. No new OneCode installation or Beta build was created. This check validates the adapter against the native page; it does not claim a full installed 1.1.3 Desktop/Remote or generation acceptance pass.

## Automated and release checks

The regression cases compare the repaired adapter against frozen 1.1.2 source using the same fixtures. The shipped source fails eight new cases; the repaired adapter passes them, including primary model captions, verified effort suffixes, both model caption layouts, semantic thinking buttons and submenu closure. The final local run passed 645 tests across 11 files covering browser adapters, model discovery, desktop/Remote model state and release-version UI. Public `npm run verify:ci` also passed, including TypeScript and production Desktop/Remote builds. GitHub build results will be recorded after packaging finishes. Local ignored tests and private native captures are not published or represented as CI tests.

The release uses GitHub native Windows/Linux runners for public verification, complete packaging, packaged-runtime smoke, embedded version/runtime validation and curated upload/checksum checks. Existing compatible users retain Windows 0.5.9 and Linux 1.0.7 minimum bases; complete packages are built from the same frozen source for fresh installations. Installed update acceptance remains separate.
