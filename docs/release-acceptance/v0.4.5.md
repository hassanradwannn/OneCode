# OneCode 0.4.5 acceptance

Windows x64 validation on 2026-10-22: **131 focused tests passed**, **0 failures and 0 skips**, across nine files covering update selection, downloads/differential behavior, bootstrap, hotfixes, install intent, registration, packaging and What's new. Public verification, privacy, notices, TypeScript, production build, full NSIS packaging and packaged runtime smoke passed. This is focused validation, not a full-suite rerun. Dependencies are unchanged.

## Regressions and update plan

A controlled open response stream proved that the UI receives a percentage greater than zero and less than 100 before the hotfix finishes; ready/100 follows verification and staging. The check does not rely on an HTTP Content-Length header. Combined-plan tests selected the exact base descriptor and installer from their own tag, staged both artifacts and produced one explicit installation handoff. A mismatched descriptor was rejected before downloading an executable.

The detached helper tests executed the base step before patching and observed exactly one final launch. Altered patch bytes were refused before the base step, and a wrong installed native inventory stopped patching. A newer declared base is installed even when the native fingerprint matches; that regression is covered. The existing explicit-work, version, cancellation, registration, traversal, checksum and rollback guards remain covered. Installer download configuration now uses a generic feed pinned to its selected tag; validation still requires that version, architecture, installer path, size and SHA-512 metadata. It cannot silently reselect a moving latest hotfix during download.

## Packaged combined activation

An isolated preserved installation received the unmodified packaged 0.4.5 base and a marked future-version 0.4.6 fixture capsule. The fixture preserved exact native ASAR unpack flags and bytes; production staging ran twice inside Electron. The production schema3 helper verified both inputs, applied the base step without a launch, checked the actual base executable's ProductVersion 0.4.5.0, applied the application patch and confirmed a loaded visible final window logging version 0.4.6. The pane showed that fixture version with four highlights. A second separate test launch stayed quiet and Settings reopened the same pane. The plan itself launched the app exactly once.

The base execution adapter copied the verified packaged base into the isolated installation instead of executing NSIS against the user's real Windows registration. Registration/shortcut checks were mocked; login/protocol registration was stubbed in memory before exact application entry resumed. The user profile was separate and the existing Windows startup entry was verified unchanged. Both fixture app processes exited. This proves packaged application sequencing and final activation; it does not claim a real NSIS installation on the user's devices. 0.4.6 is a private fixture, not a published release.

The complete 0.4.5 package contains both the earlier 0.4.4 release highlights/Settings pane and the new 0.4.5 highlights. Current and historical renderer checks passed, including modal deferral, exact notes, dark/light and short-window layouts, quiet same-version starts and reopening. Connection fixes remain in the same cumulative main source; native runtime smoke verified Electron 44.3.0, MCP, Sharp 0.35.4/libvips 8.18.6, PTY, tree-sitter and Pets.

This transition publishes eleven assets: full installer, block map, installer feed, Companion, two skills, three setup/skill documents, OneCode-Base-x64.json and SHA256SUMS.txt. It deliberately omits a capsule so older clients take the full 0.4.5 installer through their existing path. Stale hotfix files left locally are excluded from the public checksum list. A running unconfirmed successor is left alone. Power-loss recovery remains manual via retained backups or a complete installer.
