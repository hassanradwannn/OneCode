The matching acceptance build is Beta **0.7.23**, source `f9ab8b5d93dfa6e06eb9429164f09f1c92734193`. Its behavior matches the Stable source; channel/version metadata are distinct.

- Internal updater: verified download, explicit native Update now, clean shutdown and one loaded successor passed. Installed application bytes and all Companion files match the GitHub candidate. Live Companion build `21eea9e57ff4`, recorder 104, was confirmed after the isolated browser restarted.
- All 1,131 pre-update history paths remained present: 1,113 were byte-identical and 18 active mutable files changed. The deliberately deferred after-turn input retained its unsent state.
- ChatGPT: a fresh first message produced the exact native acknowledgement and canonical final. Two successive explicit Steers were acknowledged while the single original bounded process remained alive. C polled that same terminal through its own task authorization. Its final retained C's exact canonical turn after idle.
- Manual Compact: the new handoff request was sent once, acknowledged and captured as an 8,039-character summary. One successor command opened the fresh destination with the recorded model/effort request.
- The first successor expired during model preparation before destination Send. A subsequent new chat used the same GPT-6/High setting successfully, so its native limit label did not establish an account-wide quota block. The cause of that initial preparation stall remains unproved.
- The native “Open a new chat with this summary” recovery reused the same saved handoff without another summary request. It committed the successor with GPT-6 Thinking/High. Its first Core operation was an exactly authorized `write_stdin` on the original terminal; the exact expected final appeared natively and in the app. No second command was started. The original bounded process had completed naturally during the earlier wait; its complete output, final marker and matching stored digest remained accessible. This verifies the recovery path, not uninterrupted first-attempt preparation.
- Earlier native Windows checks on Beta 0.7.20 passed Gemini first message/follow-up, both Remote provider flows, and an exact trusted Stop with retained output and an unrelated production process surviving. Those are historical evidence, not fresh 0.7.23 runs.

Production Stable was not restarted or updated during acceptance.
