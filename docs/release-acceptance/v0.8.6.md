# OneCode 0.8.6 acceptance

Scope: the requested Stable recovery/continuation hotfix and cleanup of the affected receipt and browser-recovery owners.

Two reported automatic continuations had an authorized outbox Send but no delivery ACK. Canonical native history independently contained each complete task, including the original opaque credential, with an exact native question ID. Decoding the provider's Markdown escaping once recovered byte-identical task text. MCP ingress refused those tasks as receipt-pending; the evidence does not show permission settings being revoked.

The paired observation route now asks the existing input owner to reconcile that exact latest canonical question before recovery decisions. It requires the original browser, provider/conversation/session, authorized claim, retained credential, complete length-framed task and exact native question ID. Partial or changed text, another browser/question, explicit cancellation, Block and missing grants refuse reconciliation. Live and recovered receipts use one commit path. The existing active-turn/generation checks remain separate, and no prompt, tool or production task is replayed.

The silence repair previously acknowledged an error page as preserved when Continue would follow. That shortcut could leave continuation waiting inside the same broken document. It is removed: the existing one-shot reload retains its durable receipt until the replacement is ready, including provider history backoff. Existing native history Retry remains rate-limited; this repair adds no automatic resubmission of an uncertain provider Send. Redundant readiness branches and an unreachable authorization-guidance alternative were also removed.
