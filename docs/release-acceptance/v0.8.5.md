# OneCode 0.8.5 acceptance

Scope: a Windows Tailscale service-recovery hotfix. The user explicitly requested a native Tailscale restart and publication of a quick fix that keeps the repair button available. The prior full native provider matrix is not repeated for this repair.

The reported Windows failure was reproduced at the admission/presentation owner: repair required a native Funnel-ready/public-TLS-error combination, while the live failure reported public DNS errors or a pending check. Both the hidden action and backend rejection depended on that narrow verdict. Startup without an active route also had no repair path.

The system Tailscale service was restarted through administrator consent after direct service control was denied. Its process changed, BackendState returned Running with no health warnings, and its saved native Serve/Funnel configuration remained byte-for-byte unchanged. OneCode's subsequent exact public check reported ready at 2026-10-31T09:26:48.936Z, after the restart receipt at 09:26:10Z. This confirms recovery of this incident, not that every future network failure is solved.

The connection popover and Setup expose Fix network throughout Windows Tailscale connection states, independently of a probe verdict or an already-created route. The existing native service owner retains OS consent and single-flight execution. The connection owner refuses shutdown/disconnect, changed active transport and running tools. Disconnected repair does not connect automatically. Startup retains its existing prerequisite watcher. An active adapter invalidates pre-restart probe results and rechecks native custody afterward; a replaced route is retained and cannot be republished as owned. Cancellation preserves the prior diagnosis rather than inventing a TLS failure. Windows-specific action visibility does not advertise native service control on Linux or macOS.

Local validation: 143 focused service/connection/Setup tests, two mounted-renderer checks and 230 broader network/renderer checks, for 375 unique checks. The broad run initially found one old readiness fixture missing the now-required selected-browser configuration; its fixture was completed and the failing assertion passed on targeted rerun. Coverage includes disconnected/startup/daemon-wait/connected recovery, pending and error states, repeated clicks/repaints, cancellation without replay, running-tool refusal, exact route preservation, post-restart custody refusal and stale-probe suppression. Public verification passed privacy/history, notices, TypeScript and production Desktop/Remote bundles. Ignored local test files remain local at the user's request.

The release is a cumulative Stable capsule built on GitHub for Windows x64 and Linux x64. Minimum complete bases remain Windows 0.5.9 and Linux 0.8.2, subject to exact published native runtime compatibility. No native-source archive or stale installer is part of this capsule release. Frozen-source build and publication receipts follow after cloud verification.
