## Reproduced failures and repair ownership

Long ChatGPT conversations could show more native public reasoning/activity than OneCode imported. Two independent limits were reproduced: the Fiber helper repeatedly selected only the newest bounded turn groups, and the page recorder could clip one native observation at 400 KiB before durable custody. Progressive Fiber paging now keeps the newest ownership boundary while advancing through older mounted turns. Recorder 118 also enforces its transport budget against the actual serialized observation, removes optional rendered HTML before canonical prose, and preserves long UTF-8 content whenever it remains within the 1.5 MiB safe observation ceiling.

After a network timeout, Compact & Resume could remain in Preparing while the provider page was recoverable manually; a later manual provider message could then make the delayed refreshed-chat state appear, and subsequent Steer delivery could remain stranded on the stale document. The shared repair owner previously treated a resolved `tabs.reload()` request as recovery completion for compaction. 0.8.3 instead keeps the repair pending until a different registered document proves the same conversation ready. Explicit reload rejection clears the exact durable readiness receipt rather than leaving a wait for a replacement document that cannot arrive.

Fresh chats could reject a requested model even while the native browser visibly showed the same model. The failure occurred when the provider's opaque execution identifier changed between OneCode's observed catalog and native fresh-chat preparation. OneCode now freezes the observed display identity beside the exact ID at durable input/worker/resume admission. Each provider adapter still proves the actual native choice and accepts the display identity only when it resolves to one unique current choice; ambiguous or denied choices fail closed. Bridge protocol 22 makes that field a required understood contract.

The remaining presentation defects are repaired at their existing owners: shared provider HTML-to-Markdown capture keeps block code separate from neighboring prose; the connection footer retains the existing bridge state while showing a OneCode mark plus state badge; and Steer viewport reconciliation anchors the reader at the exact inserted correction rather than jumping to an absolute edge. None of these presentation repairs changes task authorization or Send replay rules.

The release also carries the post-0.8.2 Linux launcher repair. The legacy launcher identity is retired only for the verified current installation and only after any existing favourite is migrated, preserving unrelated favourites and avoiding a duplicate GNOME application identity.

## Native acceptance boundary

Installation/restart, profile preservation, selected browser/provider, exact Companion load and visible post-update acceptance are recorded separately when actually performed.
