# OneCode 0.4.2 acceptance

Windows x64 hotfix validation on 2026-10-21. Application, installer feed and Companion version: **0.4.2**. The provider adapters and authorization protocols are unchanged.

## Reproduced failure and live recovery

The installed 0.4.1 app and loopback relay were responsive. The configured ChatGPT Core connector still used the exact current hostname and owned route. Both public DNS resolvers returned ingress addresses. Exact local and private-tailnet metadata returned HTTP 200, while all three public IPv4 paths reset before TLS completed. An independent probe from the user's second Windows PC reproduced the public TLS failure. This also affected the hostname's other public services, before any OneCode HTTP handler could run.

A read-only control-map refresh, transport rebind and reassertion of the already-owned route did not restore access. A Windows administrator-approved restart of the Tailscale service restored a public metadata path and an actual ChatGPT Core command execution, which returned PowerShell 5.1.26100.9711 with exit code zero. Full Serve/Funnel configuration before and after the repair matched exactly. No account, route, credential, firewall or DNS setting was reset. No installer was run on the second PC.

This live recovery used the existing installed app and a bounded diagnostic restart helper. The hotfix integrates that service-restart action into the trusted desktop. It does not claim that every Tailscale ingress address became healthy, that third-party network failures cannot recur, or that a service restart repairs a blocked network or revoked account permission.

## Source and package validation

Focused connection, native repair, renderer, DNS, relay, MCP, lifecycle, packaging and updater coverage passed **332 tests**, with **0 failures and 0 skips** across 15 files. This is a focused run; a complete repeat of the 10,000+ test suite is not claimed. TypeScript, privacy, production build, third-party notices and native-source inventory checks passed. Dependencies are unchanged.

A hidden Electron check rendered the production recovery component with mocked IPC replies and actual pointer input at 800- and 390-pixel window widths. It verified no horizontal overflow, one repair request for repeated clicks, disabled state while pending, and checking copy after completion. The final fixture exited zero and was closed afterward.

The freshly rebuilt Windows x64 installer and packaged runtime smoke passed: Electron 44.3.0, MCP, Sharp/libvips, PTY, tree-sitter and Pets bindings. The final application archive contains the native service helper and repair IPC. Companion stamp: 606f94a07b52. Installer: 203,624,941 bytes; SHA-256: ee842e2482d714e58608f674d5972704477ea60708db148855ebee8ba276a675. The update feed hash/size and packaged/public Companion match the final inputs.

Graphify refreshed with 8,602 nodes and 27,911 edges, including the repair owner. Structural checks found no duplicate IDs, dangling edges, self-loops or duplicate edges. Existing partial-parser/empty-file warnings remain; graph completeness is not claimed.

Release publication verifies all ten server-computed asset SHA-256 digests and the exact tag commit. The large optional native-source archive is excluded.

The native helper requests Windows consent and restarts only the fixed Tailscale service. Model tools, Remote clients and background polling cannot launch the action. The current connection and route are revalidated before recovery; running tools and a changed transport refuse it. Concurrent clicks share one action. A failed or cancelled helper is not retried automatically. Late probes from before repair and late completion after Disconnect cannot publish fresh readiness.

Source tests, packaged runtime checks, the installed app and actual provider tool calls are separate evidence. Earlier 0.4.0 feature acceptance is retained in its [record](v0.4.0.md); the complete native feature matrix is not claimed rerun for this transport hotfix.
