## Desktop and automatic flows

Manual acceptance started from the desktop context meter's **Compact & resume** button for each provider. It did not use the native page's gear or manually submit a handoff. Both providers accepted the marked source request, produced a complete handoff, saved checksum-verified Markdown locally, opened their own provider's successor, and committed the existing local session to it. Each successor read the two-byte `hi` fixture and saved session history, then returned the expected test completion marker.

All four stored Markdown files matched their recorded SHA-256 receipts. Automatic tests temporarily used a 10,000-token trigger. After the final automatic transitions, ChatGPT's recorded current context was 3,418 tokens and Gemini's was 1,231. These are local estimates, not provider capacity claims.

The native tests caught and repaired two separate desktop issues: an asynchronous pickup acknowledgement could time out and reload its own sending document, and Gemini approval policy could read the new-chat selector's ChatGPT tool declarations. Neither source Send nor successor acceptance is inferred from insertion or a waiting label. The final runs required actual native question receipts and successor tool results. Regression tests also hold either provider's checkpoint while the other completes, and switch the new-chat selector without changing an existing provider's approval declarations.

The original project task was not resumed. Test instructions prohibited commands, project mutations and workers. Original settings were restored through the application: ChatGPT for new chats, automatic compaction off, threshold and advisory count 400,000. Recorded chats were preserved across installation.

## Local history

Both providers read `/sessions/<id>/history.md` through Core read. Discovery starts at `/sessions/.catalog.json`; returned paths include further history pages and saved handoff Markdown. This projects the existing local recorder rather than copying the profile into a workspace. Tests cover dated and UUID session IDs, pagination, credential removal, invalid paths and live Read files permission revocation.
